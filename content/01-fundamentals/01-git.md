# Git, который переживает вечер

**Модуль:** 01. Фундамент  
**Время:** около 25 минут  
**Дальше:** [HTTP без тумана](02-http.md)

## Цель

Отделять рабочее состояние пульта и прошивки от эксперимента. Не коммитить пароль Wi-Fi и `station_key`. Писать сообщение, по которому через неделю видно, какой контракт менялся.

## Зачем это вам

Поле — три стороны: прошивка ESP32-S3, Android-пульт и позже сервер. Они ломаются по очереди. Днём смена на площадке, вечером станц: к следующему вечеру вы не помните, какой таймаут ещё отвечал на `/v1/reading`. Коммит — записка себе, а не отчёт. Без неё «плата молчит» и «я вчера переименовал маршрут» выглядят одинаково.

## Теория

Три слоя, которые путают в начале:

1. **Рабочее дерево** — файлы, как они лежат на диске прямо сейчас.
2. **Индекс** — то, что вы явно отметили к сохранению (`git add`). Сюда не обязано попадать всё подряд.
3. **Коммит** — снимок с сообщением. К нему можно вернуться.

**Ветка** — отдельная линия снимков. `main` держите в состоянии «станц с этой прошивки и этот пульт хотя бы открывают status». Опыт («отпустить BLE перед TLS», «другой таймаут заливки GIF») живёт на своей ветке. Не вышло — вернулись на `main`, стол снова в известной точке.

В историю не кладут:

- пароль Wi-Fi, `station_key`, ключи API, JWT, файлы `.env`;
- `build/`, `.gradle/`, `local.properties` (там путь к SDK именно этой машины);
- дампы Serial и случайные ролики с карты.

`.gitignore` пишут в первый день. Секрет, однажды попавший в коммит, не лечится следующим коммитом «удалил ключ»: он остаётся в старых снимках. Частный репозиторий тоже не сейф: его копируют на второй ноутбук, в бэкап и в лог CI.

Сообщение отвечает на «что и зачем»:

```text
fix: ping станца уходит с UI-потока

OkHttp в onClick подвешивал экран, пока SoftAP молчал.
```

Перед коммитом смотрят `git status` и `git diff`. Пароль в diff — стоп, не `git add .`.

Прошивка и пульт могут лежать в разных репозиториях. Это нормально. В сообщении пульта называйте контракт платы, на который вы опирались: `GET /v1/reading`, тело текстом `OK fw:...`. Иначе через месяц стороны разъедутся, а виноватой будет «сеть».

## Разбор на примере

SoftAP станца поднята, `curl http://192.168.10.1/v1/reading` отвечает. Хотите, чтобы пульт повторял ping первые секунды, пока точка ещё глухая.

Так эксперимент не съедает единственную рабочую копию:

```bash
git status
git diff
git checkout -b experiment/ping-retry
# правка клиента: до 8 попыток, пауза около 1.5 с, сеть не на UI-потоке
git diff
git add путь/к/Esp32WifiClient.kt
git commit -m "fix: повторять ping, пока SoftAP станца поднимается"
```

Заливка файла и голос в этот коммит не входят. Один смысл — один снимок. Если опыт мёртвый:

```bash
git checkout main
```

Пара «ветка main + прошивка, которая сегодня отвечала на status» снова собрана. Следующий вечер начинается с неё, а не с раскопок.

## Упражнения

1. В `git diff` есть строка `CFG:cloud:set:example.host\tESP-001\tсекрет`. Что сделать до коммита? Почему следующий коммит «убрал секрет» историю не чистит?
2. Напишите сообщение (заголовок и одна строка причины): хендлер `/api/display` больше не декодирует GIF внутри себя, а только запоминает путь и ставит флаг.
3. `main` отвечает на status. Нужно проверить, хватает ли памяти, если держать BLE и TLS одновременно. Как назвать ветку и какой одной командой вернуться к рабочему скетчу?

### Ориентир для самопроверки

1. Убрать секрет из файла и из индекса, в коммит его не класть. Ранее опубликованный снимок с секретом надо считать утёкшим: секрет меняют на устройстве и в облаке, а не «затирают» новым коммитом.
2. В заголовке — поведение, не список файлов. В причине — зачем: HTTP-хендлер должен быстро ответить, кадр рисует `loop`.
3. Ветка вроде `experiment/ble-vs-tls`. Откат рабочей линии: `git checkout main`. Саму плату после этого ещё нужно прошить снимком с `main`, если вы уже залили экспериментальную прошивку. Git помнит исходник, не содержимое флеша.

## Типичные ошибки

- `git add .` там, где рядом лежат ключи, APK и чужой `.env`.
- Один коммит «фикс» на интерфейс, прошивку и случайный чертёж.
- Править единственную копию `main`, с которой станц сегодня включался.
- Хранить секрет облака в `strings.xml`, потому что репозиторий частный.
- Не игнорировать `build/` Arduino: история раздувается сотнями мегабайт, которые не помогают отладке.

## Чеклист

- [ ] По `git status` понятно, что моё, что мусор, что секрет.
- [ ] В истории нет пароля Wi-Fi и `station_key`.
- [ ] `main` — последнее состояние, с которого станц отвечает на status.
- [ ] Эксперимент на отдельной ветке, откат исходников — `git checkout main`.
- [ ] Сообщение называет контракт, который изменился.
