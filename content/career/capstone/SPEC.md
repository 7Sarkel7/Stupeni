# DeskNode — спецификация капстоуна

**Уровень:** J закрывает проект. Пункты **M** не нужны, чтобы откликаться на junior.  
**Где делать:** новый публичный репозиторий, не форк Ступеней и не каталог внутри этого репозитория.  
**Чего здесь нет:** исходников приложения, прошивки и «правильного» README. Это задание. Эталона проекта нет специально.

DeskNode — лампа на столе. Телефон в той же сети включает и выключает её и показывает, отвечает ли плата. Один экран, один контракт, тесты на чистую логику, README на двух языках. Этого достаточно для разговора на junior. Это не платформа умного дома и не продолжение учебной метеостанции «Поле» под другим именем: на собеседовании вы рассказываете про этот репозиторий.

Опора: модули Ступеней 01–03 и уроки C1–C4. Прошивку пишете в том же духе, что `setup`/`loop` и слой действия. Экран — в том же духе, что редьюсер из лаборатории, но типы называете заново (`DeskUiState`, не копипаста `LampState` из учебного модуля).

## Не делаем

- Аккаунт, облако, push, магазин приложений.
- Несколько комнат, сцены, расписания.
- Прошивку «как в станции»: файлы, голос, лестница транспортов целиком.
- Секреты, пароль от Wi-Fi и ключи в git.
- Заявку «middle» и строку «коммерческий опыт N лет» на основании этого репозитория.

## Продукт одной фразой

Человек вводит адрес платы, видит, включена ли лампа, и нажимает одну кнопку. Если платы нет, он читает фразу, а не трассу исключения.

## Контракт

Плата слушает HTTP на порту 80. Телефон ходит на `http://<ip>`. JSON, `Content-Type: application/json`. Поля, которых нет в этой спеке, клиент игнорирует, а не падает.

### `GET /api/lamp`

Ответ `200`:

```json
{"uptimeSec": 12, "lampOn": true, "fw": "0.1.0"}
```

- `uptimeSec` — целое, секунды с запуска прошивки, не с момента включения лампы.
- `lampOn` — состояние, которое плата считает истинным.
- `fw` — строка версии, которую вы сами подняли в коде и в README.

### `POST /api/lamp`

Тело:

```json
{"on": false}
```

Успех `200` и то же тело, что у `GET /api/lamp`, уже с новым `lampOn`.

Ошибка тела `400`:

```json
{"error": "on must be boolean"}
```

Нет поля `on`, поле не boolean, тело не JSON — один и тот же `400` и та же строка. Не придумывайте пять разных текстов: на скрининге вы объясняете один контракт.

Других кодов в J не требуется. Если позже добавите занятость устройства, это будет `503` с `{"error":"..."}` и попадёт в политику повтора. Для J достаточно `200` и `400`.

Таймауты клиента зафиксируйте в README числами, которые реально стоят в коде. Разумный старт: соединение 3 секунды, чтение 5 секунд. Повтор — не больше двух дополнительных попыток, пауза из той же идеи, что `backoffMs` в лаборатории (можно проще: 300 мс и 600 мс). Повторяют обрыв сети и `503`, если он появится. `POST` при `500` не повторяют. `400` не повторяют. Это прямое следствие урока про идемпотентность: включение лампы не должно случайно уйти три раза, если вы не умеете отличить «плату не слышно» от «плату слышно, запрос плохой».

## Прошивка, уровень J

Плата, с которой вы уже делали модуль 03. Если на столе ESP32 нет всю неделю, временно допустим свой маленький стенд на компьютере с тем же контрактом. В README так и напишите: «стенд на ноутбуке, GPIO не подключён». Не пишите «устройство в проде». Как только плата есть, стенд остаётся только для проверки контракта, демо показывают с платы.

Обязательно:

- `setup` поднимает Wi-Fi и сервер, `loop` не блокируется длинным ожиданием. Короткий опрос сокета, как в модуле 03.
- `GET /api/lamp` и `POST /api/lamp` делают одно и то же изменение лампы через одну функцию, а не через два разных куска, которые разъедутся.
- Пин записан в README. Нет светодиода — храните флаг в памяти и честно назовите это software lamp. Есть светодиод или реле — переключайте его и напишите, какой пин и какая логика уровня.
- Неизвестный путь — `404` без падения прошивки.
- Секрет сети не коммитится. Шаблон вроде `secrets.h.example` с пустыми кавычками — нормально.

Проверка, которую вы сохраняете в README (подставьте свой IP):

```bash
curl -sS http://192.168.1.42/api/lamp
curl -sS -H 'Content-Type: application/json' -d '{"on":true}' http://192.168.1.42/api/lamp
```

Оба ответа — JSON из контракта. Третий запрос с телом `{}` даёт `400`.

## Android, уровень J

Один экран на Jetpack Compose и Material 3. Так собран пульт в модуле 02, так вы защищаете junior-экран. Одна Activity вызывает `setContent`. Кадр — composable, снимок — ViewModel.

Чужой старый проект на View и XML вы можете прочитать. Новый экран DeskNode так не собирают. `AndroidView` на этой лампе не нужен: отдельного чужого виджета нет.

Экран:

- поле IP, кнопка «обновить», кнопка лампы;
- компоненты Material 3 (`TextField`, `Button`, `Text`, `Scaffold`), одна `MaterialTheme`;
- IP переживает перезапуск приложения;
- пока идёт запрос, кнопки не нажимаются второй раз;
- успех показывает «включена» или «выключена» и `uptime`;
- обрыв, таймаут, `400`, кривой JSON — разные человеческие фразы. Трассу на экран не кладут, её пишут в лог;
- cleartext разрешён только к частной сети, не на произвольные хосты в интернете;
- номер Compose BOM копируют со [страницы BOM](https://developer.android.com/develop/ui/compose/bom) в день проекта. Рядом в Gradle — дата и ссылка. Номер из чужого README двухлетней давности не берут. Карта доков: [Jetpack Compose](https://developer.android.com/develop/ui/compose/documentation), [Material 3](https://developer.android.com/develop/ui/compose/designsystems/material3).

Второй экран в J не требуется. Пульт станции уже тренирует Navigation 3 и `LazyColumn`. Если на лампе всё же появится второй маршрут, лист получает лямбду, в ключе нет всей модели лампы.

Архитектура, которую вы защищаете:

- одно состояние экрана и чистая функция перехода, по духу как `reduce` из урока MVVM, с новыми именами;
- наружу `StateFlow`, корень экрана собирает `collectAsStateWithLifecycle`, вниз уходят снимок и события;
- сеть за интерфейсом репозитория. ViewModel не собирает OkHttp руками в каждом методе;
- смена UI на главном потоке, сокет не на главном и не в теле composable. Это модуль 02, здесь его не отменяют;
- юнит-тесты без эмулятора: переходы состояния и разбор кода/тела в ошибку. Репозиторий в тесте фейковый. Один инструментальный тест кадра — по желанию, как в модуле 02; в порог J он не входит.

`minSdk` 26, если нет причины ниже. Версию пишете в README.

## Репозиторий

Имя вроде `desknode`. В корне:

- `README.md` — два языка, см. каркас ниже;
- `LICENSE` — MIT, если вам так спокойно;
- `.gitignore` для Android и прошивки, без `local.properties` и без паролей;
- каталог прошивки и каталог приложения;
- GitHub Actions: на push и на pull request гоняется юнит-тест приложения. Эмулятор в CI не требуется.

История читается. «фикс» и «update» не подходят, это уже было в модуле 01. Один pull request вы открываете сами на свою ветку, даже если ревьюер — вы через день: в описании что изменилось, как проверить, чего не делали. Годится маленький кусок: повтор при обрыве или ещё один тест. Вливать в main сразу пачкой без описания — слабее для портфолио.

## Каркас README

Пишете сами, простыми фразами. Английский может быть коротким. Заголовки держите, чтобы человек с телефона нашёл демо.

```markdown
# DeskNode
## What it is
## What it is not
## Hardware
## HTTP contract
## Run the firmware
## Run the app
## Tests
## Limits

# DeskNode
## Что это
## Чем это не является
## Железо
## Контракт HTTP
## Как прошить
## Как открыть приложение

```

В «ограничениях» одна честная фраза: локальная сеть, один узел, без облака, автор делал вечерами, коммерческой установки нет.

## Вехи

Каждая веха — отдельный осмысленный коммит или короткая ветка. Дата в скобках — ориентир при 4–6 часах в неделю после уроков C1–C4, не дедлайн работодателя.

### M0. Пустой репозиторий (вечер)

Репозиторий публичный, лицензия, gitignore, README из заголовков на двух языках, в тексте честно написано «ещё не мигает». В README есть дата, когда вы хотите закрыть M4.

Готово, когда незнакомый человек открывает репозиторий и понимает, что появится, и не находит паролей.

### M1. Контракт жив (неделя)

Прошивка или временный стенд отвечает на три `curl` из раздела контракта: status, лампа включена, битое тело → 400. Вывод curl вставлен в README как пример, IP замазан или указан как пример `192.168.1.42`.

Готово, когда команда из README копируется и даёт JSON, а не HTML роутера.

### M2. Экран и состояние (неделя)

Приложение на Compose по введённому IP показывает статус. Кнопка лампы меняет его. Редьюсер покрыт тестами: покой, загрузка, включено, выключено, ошибка, повторный тап во время загрузки игнорируется. Сеть в этих тестах не ходит.

Готово, когда `gradlew test` (или эквивалент модуля) зелёный локально и кнопку нельзя заспамить.

### M3. Ошибки человеком (неделя)

Обрыв кабеля или выключенная плата даёт фразу. `400` даёт другую фразу. Кривой JSON — третью. Политика повтора совпадает с тем, что написано в README. IP сохранён.

Готово, когда вы можете на демо выдернуть питание и показать экран, а не закрытое приложение.

### M4. Портфолио (неделя)

CI зелёный на GitHub. README заполнен на двух языках. Есть один PR с текстом. В README команда, которой вы сами прогоняете тесты. Скриншот экрана или честное фото платы — по желанию, без паролей в кадре.

Готово, когда вы проходите рубрику ниже без нулей по пунктам J и отправляете резюме со ссылкой.

### M5. По желанию, уровень M

Один пункт, не все сразу:

- запомнить последний успешный статус и показать его серым, пока сеть молчит, подписав «последнее известное»;
- или найти плату в локальной сети без ручного IP (mDNS), если это правда работает у вас на кухне.

Плюс полстраницы в `docs/design.md`: кто источник правды (плата), что телефон только показывает, что будет, если телефон и плата разошлись. Это задел под конспект system design, не отдельный продукт.

M5 не требуется для отклика на junior.

## Критерии приёмки

J считается сданным, когда все пункты ниже выполнены. M5 не входит.

- [ ] Контракт `GET /api/lamp`, `POST /api/lamp`, `400` на плохое тело. Проверено curl и совпадает с README.
- [ ] Одна функция на плате меняет лампу, HTTP только вызывает её.
- [ ] `loop` не стоит в длинном `delay`, пока обслуживается HTTP.
- [ ] Экран: IP, обновление, переключение, блокировка кнопок на время запроса.
- [ ] IP переживает перезапуск.
- [ ] Ошибки сети, `400` и кривой JSON различимы по тексту на экране.
- [ ] Сокет не на главном потоке.
- [ ] Юнит-тесты редьюсера и разбора ошибки зелёные в CI.
- [ ] Cleartext не открыт на произвольные хосты в интернете.
- [ ] README на русском и английском, ограничения названы.
- [ ] В git нет паролей и ключниц.
- [ ] Есть хотя бы один PR с описанием, что проверить.
- [ ] В резюме проект описан как личный, без коммерческого внедрения.

## Рубрика для самопроверки

Поставьте себе 0, 1 или 2. Ноль по любому пункту J — к отклику рано, даже если «в среднем неплохо».

| Пункт | 0 | 1 | 2 |
| --- | --- | --- | --- |
| Контракт | curl не повторяет README или README молчит | curl совпал, коды ошибок размазаны | status, лампа и 400 стабильны, пример в README |
| Прошивка | логика лампы скопирована в два обработчика | одна функция, но `loop` иногда блокируется | одна функция, цикл обслуживает сеть |
| Состояние UI | флаги раскиданы по кнопкам | одно состояние, тестов мало | редьюсер и тесты на загрузку, успех, ошибку, повтор |
| Ошибка человеку | трасса или пустой экран | одна фраза на всё | сеть, 400 и битый JSON различаются |
| Потоки | сеть в обработчике нажатия | сеть уехала, кнопки всё ещё спамятся | IO отдельно, кнопки гаснут на время запроса |
| Тесты в CI | только локально или красные | CI есть, падает от случая к случаю | последний push зелёный, команда написана в README |
| Git | один коммит «initial» со всем подряд | коммиты по вехам, PR без текста | вехи видны, PR говорит, как проверить |

Junior-порог: нет нулей по строкам J, честность равна 2, тесты в CI не ниже 1. Middle этот репозиторий сам по себе не выдаёт. M5 с двойкой — аргумент наниматься junior и говорить, что границу слоёв вы уже трогали.

## Демо на три минуты

Так рассказываете, если попросят экран.

1. Плата в сети, `curl` status.
2. Кнопка в приложении, лампа меняется, status совпадает.
3. Питание платы снято, на экране фраза, приложение живо.
4. Открыт зелёный прогон тестов или бейдж CI.

Фраза о себе, без украшений: «Собрал локальный узел: ESP32 и Android-клиент. Контракт JSON, состояние экрана отделено от сокета, юнит-тесты гоняются в GitHub Actions. Облака и коммерческой установки нет.»
