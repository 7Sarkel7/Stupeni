## Цель

Выбрать `List`, `Set` или `Map` под задачу пульта и сказать, какая операция смотрит все элементы, а какая ищет по ключу. Написать подсчёт слов циклом.

## Зачем это вам

Модуль 02 уже увёл сокет с кнопки. На скрининге (первый короткий этап собеседования, где проверяют базовые знания) до сокета обычно спрашивают, куда вы кладёте данные. Станция маленький, вопрос тот же: история ошибок, множество уже показанных путей и последний ответ по IP — три разных хранения. Путаница здесь дешёвая в учебнике и дорогая в коде, который кто-то будет читать на ревью (проверка вашего кода другим человеком до того, как изменения попадут в проект).

Урок целиком на уровне J. Его не откладывают до middle (мидл, middle — разработчик среднего уровня, который сам ведёт задачу до конца).

## Теория

`List` помнит порядок и разрешает одинаковые элементы. Взять элемент по индексу дёшево. Найти «есть ли такая строка» без предварительной подготовки значит пройти список. Для пульта это лента ошибок: два одинаковых «нет связи» подряд — два события, порядок нужен.

`Set` хранит уникальные значения. Проверка «такое уже было» в среднем не сканирует всё множество. Порядок для экрана он не обещает. Сюда кладут id команды, которую уже отправили, чтобы не плодить дубль.

`Map` хранит ключ и значение. Ключ один. «IP → последнее тело status» — карта. Список пар, который каждый раз просматривают с начала, на десяти адресах ещё терпим, на вопросе «что будет на тысяче» уже нет.

Мутабельность. `listOf` и `mapOf` после создания не дают добавить элемент. `mutableListOf` даёт. Состояние экрана спокойнее собирать заново, чем менять список, который уже увидела кнопка. Иначе сеть и UI (пользовательский интерфейс: всё, что видит и нажимает человек) смотрят в разные моменты одной коллекции.

`for (item in list)` вместе с `list.remove(item)` внутри цикла роняет `ConcurrentModificationException`. Удаляют через новый список или `removeAll`, не через ту же коллекцию, по которой идут.

Цена словами. «Линейно» значит: элементов в десять раз больше — шагов примерно в десять раз больше. Поиск в `HashMap` и `HashSet` в среднем не листает все записи. Это устройство таблицы, не обещание, что каждый вызов мгновенный. На junior (джун, junior — разработчик начального уровня) хватает фразы: список для поиска значения сканируется, карта по ключу — нет.

Порядок ключей. Обычная хеш-карта (SHA, хеш — уникальный идентификатор коммита из букв и цифр) не для порядка на экране. `linkedMapOf` помнит порядок вставки. Если от порядка зависит тест или список на экране, это выбирают явно.

Ключ карты должен сравниваться так, как вы думаете. У `data class` равны одинаковые поля. У обычного класса без своих `equals` и `hashCode` равны только ссылки: два с виду одинаковых объекта станут двумя ключами. Модели — следующий урок.

## Разбор на примере

Пульт помнит три вещи.

Ошибки — `List<String>`. Порядок нажатий и повторы важны.

Уже показанные пути файлов — `Set<String>`. Важно «был или нет».

Последний status по адресу — `Map<String, String>`, ключ IP.

Подсчёт слов к станции не привязан. Его дают, потому что на нём видно, умеете ли вы пройти строку и сложить частоту. Готовой функции в уроке нет.

Один шаг на бумаге. Текст `Дождь дождь, датчик`. Режете по всему, что не буква и не цифра. Три токена (секретная строка-пропуск, которая подтверждает, кто вы), нижний регистр, в карте `дождь` равен 2, `датчик` равен 1. Пустые куски между запятыми выбрасываете.

## Упражнения

Сигнатуры уже в `lab/src/main/kotlin/dev/stupeni/career/Collections.kt`. Меняете только тела. Намёк не копировать.

`wordCount`:

- слово — буквы и цифры, любой язык, остальное разделитель;
- регистр не различаете;
- пустая строка и строка из одних знаков — пустая карта;
- порядок ключей — порядок первого появления слова.

`topWords`:

- берёт результат `wordCount`;
- более частое слово раньше;
- при равной частоте раньше слово, которое меньше по алфавиту;
- `n <= 0` и пустой текст дают пустой список.

Пишите циклом и `MutableMap`. Без `groupBy` и `groupingBy`: на скрининге попросят цикл. Тест проверяет ответ, за форму отвечаете вы.

```bash
cd content/career/lab
./gradlew test --tests dev.stupeni.career.WordCountTest
```

Красный прогон до вашей реализации — норма, не поломка Gradle.

## Типичные ошибки

- `Set` там, где пользователю нужен порядок событий.
- Линейный поиск по списку в месте, где ключ уже известен.
- Менять коллекцию, которую только что отдали на экран.
- Считать библиотечную группировку объяснением устройства.
- Открыть эталон в ту же минуту, когда тест впервые покраснел.
