# Clean lite: три слоя

**Модуль:** C3. Архитектура экрана  
**Уровень:** J, абзац **M.** можно отложить  
**Время:** около 40 минут  
**Лаборатория:** `LoadLampTest`  
**Намёк:** [solutions/08-clean-lite.md](solutions/08-clean-lite.md)  
**Дальше:** [Корутины так, как на ревью](09-coroutines-work.md)

## Цель

Поставить между экраном и сокетом маленький объект, который умеет «прочитать лампу». ViewModel зависит от интерфейса. Тест подсовывает фейк и не включает Wi-Fi.

## Зачем это вам

Редьюсер из прошлого урока не знает, откуда возьмётся `true`. Если ViewModel сама создаёт OkHttp, тест либо идёт в сеть, либо вы начинаете мокать полклиента. На junior достаточно трёх слоёв, без десятка модулей Gradle и без слова Clean как украшения.

J — интерфейс репозитория, один сценарий «загрузить», фейк в тесте. **M.** — куда деть запись «включить» и почему use case не разрастают папками раньше второй фичи.

## Теория

Слой UI рисует снимок и шлёт события. На новом экране это composable Material 3. Activity вызывает `setContent` и не собирает JSON. Фрагмент и XML остаются в чужих старых проектах, в новый пульт их не кладут.

Слой данных ходит в плату и возвращает `Result` или модель, не строку для Toast. OkHttp живёт здесь. Сюда же потом встанет разбор кода через `mapHttp`.

Между ними тонкий сценарий. В лаборатории он называется `LoadLamp`. Он получает репозиторий в конструкторе. Метод `execute` берёт текущий снимок. Если уже идёт загрузка, репозиторий не вызывается и снимок тот же. Иначе снимок переводят в загрузку через `reduce`, зовут `fetchLampOn()`, успех и неудачу снова пропускают через `reduce`.

Почему сценарий, а не метод репозитория «верни уже готовый LampState». Репозиторий не должен знать про фазы экрана. Ему достаточно `Result<Boolean>`. Экранные слова «загрузка» и «нет связи» живут выше. Иначе каждая новая вёрстка тащит за собой сокет.

Фейк в тесте — класс на десять строк: запоминает, сколько раз его позвали, возвращает заранее положенный `Result`. Это не библиотека моков. На скрининге спокойнее показать ручной фейк и сказать, что он проверяет.

**M.** Вторая операция, «установить лампу», — второй метод репозитория, не флаг внутри `fetch`. Use case имеет смысл, когда сценарий длиннее одного вызова: загрузка, решение повторить, запись. Пока сценарий в три строки, не заводите пакеты `domain/usecase/lamp/impl`. На middle спросят обратное: почему вся сеть осталась во ViewModel. Ответ «репозиторий один, сценарии появятся со второй фичей» звучит взрослее, чем пустая архитектура на вырост.

Ошибки. `Result.failure` с текстом становится событием `Failed` с этим текстом. Пустое сообщение исключения становится «нет связи» уже внутри `reduce`, не второй самодельной строкой в `LoadLamp`. Одна точка текста, иначе тест и экран разъедутся.

## Разбор на примере

Открытие экрана. Снимок — покой. `execute` переводит его в загрузку, репозиторий возвращает успех `true`, наружу уходит «включена». ViewModel кладёт этот снимок в `StateFlow` или в поле, с которого обновляется UI. В лаборатории `StateFlow` нет: возвращается готовый снимок, и этого достаточно, чтобы проверить порядок.

Пользователь нажал обновление, пока запрос ещё идёт. Снимок уже «загрузка». `execute` возвращает его сразу, счётчик фейка не растёт. В приложении это значит, что вы не открываете второй сокет.

Плата не ответила. Фейк возвращает `Result.failure`. Снимок — сбой с текстом исключения. Сокета в тесте не было.

## Упражнения

Напишите тело `LoadLamp.execute`. Интерфейс `StatusRepository` уже объявлен. `reduce` должен быть вашим, из прошлого урока: этот тест зовёт оба.

Поведение:

- фаза `Loading` — репозиторий не вызывать;
- иначе один вызов `fetchLampOn`;
- успех и ошибка проходят через `reduce`;
- пустой текст ошибки заканчивается фразой «нет связи».

```bash
cd content/career/lab
./gradlew test --tests dev.stupeni.career.LoadLampTest
```

### Самопроверка

- Репозиторий не упоминает `Phase`.
- Пока идёт загрузка, счётчик фейка нулевой, если стартовать уже из загрузки.
- Намёк [solutions/08-clean-lite.md](solutions/08-clean-lite.md) закрыт.

## Типичные ошибки

- Создавать OkHttp внутри сценария, который хотите тестировать.
- Возвращать из репозитория уже русскую фразу для конкретной вёрстки.
- Звать сеть, даже если снимок говорит «уже гружусь».
- Подключать Mockito раньше, чем написан один ручной фейк.
- Называть три пакета Clean Architecture и класть всю логику в один файл в `ui`.
