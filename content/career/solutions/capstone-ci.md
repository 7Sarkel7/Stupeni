# Намёк. CI капстоуна

Готового файла workflow (файл, в котором описано, когда и какие шаги GitHub запускает автоматически) здесь нет. Свой соберите из шагов и подставьте каталог, где лежит `gradlew` вашего приложения.

- Запуск на push (пуш — отправка ваших коммитов на сервер, например на GitHub) и на pull request (просьба на GitHub проверить ваши изменения и добавить их в основную ветку).
- Машина Ubuntu.
- Checkout (чекаут — переключение рабочей папки на другую ветку или коммит) репозитория.
- JDK той версии, которой вы собираете локально. В README та же цифра.
- Команда юнит-тестов из каталога приложения, не из корня, если `gradlew` лежит глубже.
- Эмулятор не требуется для порога junior (джун, junior — разработчик начального уровня).
- Секреты в файл не кладите.
- Если шаг красный, его не комментируют «пока что». Чинят тест или код.

Сверьтесь с документацией GitHub Actions по `setup-java` и `checkout` на день, когда пишете файл: имена версий действий там живые, в этом намёке их нет специально.
