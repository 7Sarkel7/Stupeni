# Капстоун: взять SPEC и сделать

**Модуль:** капстоун, после C1–C4  
**Уровень:** J, веха M5 помечена в спеке и не нужна для отклика  
**Время:** около 30 минут на этот урок, дальше несколько недель вечеров  
**Спека:** [capstone/SPEC.md](capstone/SPEC.md)  
**Готового проекта в `solutions/` нет.**  
**Дальше:** [System design lite](14-system-design.md) — конспект, его можно читать параллельно с откликами

## Цель

Понять, как идти по спеке DeskNode, не ища готовый проект. Завести свой репозиторий и первую веху M0.

## Зачем это вам

Лаборатория проверяла функции. Нанимающий открывает не её, а отдельный репозиторий, где есть прошивка или честный стенд, экран, тест и README. Спека написана так, чтобы её можно было выполнить после модулей 01–03 и уроков C1–C4. Она не заменяет эти уроки и не содержит исходников. Если положить сюда готовый DeskNode, на собеседовании нечего будет защищать: первый вопрос «покажите, где переключается пин» развалит чужой код.

Урок на уровне J. Middle-веха в спеке необязательна.

## Теория

Спека — контракт между вами и будущим читателем README. Её не «улучшают» в первую неделю. Сначала три `curl` и один экран, как написано. Идеи про расписание лампы и аккаунт записывают в конец README в ограничения, а не в код.

Репозиторий новый. Не каталог внутри Ступеней и не форк этого курса. Имя вроде `desknode`. История коммитов с первой вехи должна быть вашей.

Порядок вех M0–M4 в спеке совпадает с порядком отладки из модуля 01: сначала контракт снаружи (`curl`), потом экран, потом человеческая ошибка, потом CI и текст для чужого человека. Перескакивать на GitHub Actions, пока `curl` не совпал с README, — способ получить зелёный бейдж и мёртвую лампу.

Имена в приложении новые. Редьюсер по духу как в уроке MVVM, типы не копируют учебный `LampState` файл в файл. Иначе вы не отличите, что поняли, а что перенесли. Правила переходов можно держать рядом и писать заново.

Экран — Jetpack Compose и Material 3, как в спеке и в уроке [20](20-compose-screen.md). Номер BOM берут со страницы документации в день проекта. Kotlin Multiplatform спека не требует.

Временный стенд на ноутбуке вместо платы допустим, если ESP32 нет всю неделю. В README это написано прямо. В резюме тогда нет фразы «прошил устройство». Как только плата на столе, демо делают с неё.

Подсказка по YAML для CI лежит в [solutions/capstone-ci.md](solutions/capstone-ci.md). Её открывают, если свой workflow не собирается около 40 минут. Остальные файлы эталона к проекту не относятся.

Отклики уходят после M4 и рубрики без нулей. Конспект system design не является входным билетом.

## Разбор на примере

Вечер M0. Создали пустой публичный репозиторий. Появились `LICENSE`, `.gitignore`, `README.md` с заголовками на русском и английском из спеки. Внутри «Что это» одна фраза: локальное включение лампы с телефона, ещё не мигает. В ограничениях: нет облака, нет коммерческой установки. Дата, когда хотите закрыть M4, стоит в README, чтобы вечер не расползался.

Следующий вечер — не «немного Android и немного прошивки», а M1: три запроса из спеки. Пока они не зелёные, экран не начинают. Иначе неясно, врёт кнопка или плата.

## Упражнения

1. Прочитайте [capstone/SPEC.md](capstone/SPEC.md) целиком, включая рубрику. Отметьте карандашом пункты J, которые вам пока неясны. Неясное перечитайте в уроке C2 или C3, не ищите чужой репозиторий лампы.
2. Заведите публичный репозиторий и закройте веху M0 так, как она описана в спеке. Ссылку храните у себя.
3. В черновике резюме из урока 12 добавьте пустую строку «DeskNode — после M4», без описания функций, которых ещё нет.
4. Напишите себе расписание вечеров до M4 на четыре недели. Сдвиг недели допустим. Отмену вехи M1 ради иконки — нет.

Готового кода, который можно сдать вместо этого, в `solutions/` нет. Это и есть условие урока.

### Самопроверка

- Репозиторий открывается без логина, паролей внутри нет.
- README на двух языках говорит, чего ещё нет.
- Вы можете показать пальцем в спеке, какая веха следующая и какой `curl` её закроет.

## Типичные ошибки

- Форкнуть Ступени и положить лампу рядом с уроками.
- Начать с облака или с BLE, хотя спека про локальный HTTP.
- Скопировать учебный редьюсер без переименования и не суметь его рассказать.
- Написать в README «production-ready».
- Открыть чужой умный дом «для справки» и унести оттуда половину экрана.
- Ждать конспект C5, чтобы создать репозиторий.
