## Цель

Читать и писать типы вида `(Int) -> String`, `() -> Unit`, `(A, B) -> C`. Написать функцию, которая принимает функцию и функцию, которая возвращает функцию. Передавать ссылки `::name`.

## Зачем это вам

`onClick: () -> Unit`, `onResult: (Result<Status>) -> Unit`, `content: @Composable () -> Unit`, `block: suspend CoroutineScope.() -> Unit` — всё это функциональные типы. Пока вы не читаете их так же свободно, как `Int`, чужой код приходится угадывать.

## Теория

**Тип функции** записывают так: `(типы параметров) -> тип результата`.

| Тип | Что за функция |
| --- | --- |
| `() -> Unit` | без параметров, ничего полезного не возвращает |
| `(Int) -> Int` | принимает число, возвращает число |
| `(String, Int) -> Boolean` | два параметра, возвращает булево |
| `(Int) -> (Int) -> Int` | принимает число, **возвращает функцию** |
| `Int.() -> String` | функция с получателем: внутри `this` — это `Int` |

`Unit` — «ничего полезного»; в лямбде с типом `-> Unit` последнее выражение игнорируется, ошибки не будет.

**Имена параметров в типе** — только документация: `(host: String, port: Int) -> Unit`. Подсказывают, что значит каждый аргумент, на вызов не влияют.

**Функция высшего порядка** — функция, которая принимает функцию или возвращает функцию.

```kotlin
fun applyTwice(x: Int, f: (Int) -> Int): Int = f(f(x))

applyTwice(3) { it * 2 }      // 12
applyTwice(3, ::increment)    // зависит от increment
```

В теле `f(f(x))` — вызов параметра `f` как функции. Так выглядит почти вся «магия» стандартной библиотеки: `filter` — это функция, которая принимает `(T) -> Boolean` и вызывает его для каждого элемента.

**Функция возвращает функцию.**

```kotlin
fun multiplier(k: Int): (Int) -> Int = { x -> x * k }

val triple = multiplier(3)
println(triple(7)) // 21
```

`multiplier` вернула лямбду, которая «помнит» `k` — это замыкание, [урок 06](06-capture-inline.md).

**Ссылки на функции.**

- `::double` — функция верхнего уровня.
- `String::length` — метод класса: функция `(String) -> Int`.
- `user::greet` — метод конкретного объекта (привязанная ссылка).
- `::Point` — ссылка на конструктор.

```kotlin
listOf("a", "bb").map(String::length)   // [1, 2]
names.forEach(::println)
```

Ссылку используют, когда лямбда только вызывает одну существующую функцию с теми же параметрами. Не нужно: `{ it.length }` и `String::length` равны, выбирайте читаемое.

**Функции с получателем.** Тип `T.() -> R` — лямбда, внутри которой `this` равен `T`. Так сделаны `apply`, `with`, `buildString` и DSL (мини-язык внутри основного, заточенный под одну задачу): `Row { Text("a") }`. Подробнее — [scope-функции](09-scope-functions.md) и [extension](10-extensions.md).

**Алиас (короткое имя, подставляемое вместо длинного).** Длинный тип удобно назвать: `typealias Handler = (String) -> Unit`. Это только имя, не новый тип.

**fun interface.** Когда нужны имя и документация, но по сути это одна функция: `fun interface Clock { fun now(): Long }`. Можно создать лямбдой: `val fake = Clock { 42L }`. Хорошо для зависимостей, которые подменяют в тесте.

**suspend-функции в типе.** `suspend () -> Unit` — лямбда, которую можно вызвать из корутины. Пример — `launch { ... }`: блок, который вы передаёте, имеет такой тип, поэтому внутри можно вызывать `delay` и `withContext`.

## Разбор на примере

Повтор с обратным вызовом. Вместо флага `isRetry` внутри сетевой функции:

```kotlin
fun <T> retry(times: Int, block: (attempt: Int) -> T?): T? {
    for (i in 0 until times) {
        val result = block(i)
        if (result != null) return result
    }
    return null
}

val ip = retry(3) { attempt ->
    println("попытка $attempt")
    pingOrNull()
}
```

`block` — параметр с функциональным типом. Вызывающий решает, что именно повторять. `retry` не знает про сеть, про станцию, про пульт. Эту функцию вы допишете сами в `firstSuccess` ([работа](07-homework-lambdas.md)).

Второй пример, уже про Android:

```kotlin
class LampViewModel(
    private val load: suspend () -> Status,
    private val onError: (String) -> Unit,
)
```

В тесте вместо настоящей сети передают `{ Status("test") }` и `{ errors += it }`. Зависимость-функция — самый короткий интерфейс.

## Упражнения

1. Что за тип у `val f = { a: Int, b: Int -> a + b }`? Запишите его явно. А у `val g = { println("x") }`?
2. Напишите `fun twice(action: () -> Unit)`, вызывающую `action` два раза. Вызовите её хвостовой лямбдой и ссылкой на любую `fun hello()`.
3. Напишите `fun adder(k: Int): (Int) -> Int` и посчитайте `adder(10)(5)`.
4. Реализуйте `compose` из `Lambdas.kt`: сначала `first`, затем `second` к результату. Проверьте: `compose({ it + 1 }, { it * 10 })(3)` даёт 40.
5. Что за тип у `String::length`? Вызовите `listOf("a", "ccc").map(String::length)` и распишите шаги.
6. Опишите `typealias Predicate<T> = (T) -> Boolean` и используйте в собственном `fun <T> List<T>.countWhere(p: Predicate<T>): Int` без стандартного `count`.
7. Прочитайте вслух три типа из Compose: `onClick: () -> Unit`, `onValueChange: (String) -> Unit`, `content: @Composable ColumnScope.() -> Unit`. Скажите, кто их вызывает: ваш код или Compose.

### Самопроверка

- Вы можете написать тип «функция от двух строк в булево» без подсказки.
- Объясняете, чем `compose` отличается от `applyTwice` (возвращает функцию, а не значение).

## Типичные ошибки

- Путать `(Int) -> Unit` и `() -> Int`.
- Забыть вызвать параметр-функцию: `f` без скобок — это значение, а не результат.
- Ссылка на метод класса без учёта получателя: `String::length` берёт `String` первым параметром.
- Писать `Unit` вручную в лямбде, когда последнее выражение уже не важно.
- Выдумывать `typealias`, когда достаточно читаемой лямбды.
