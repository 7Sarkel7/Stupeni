## Цель

Объяснить разницу `val` и `var`, не бояться `Int?` и `String?`, выбрать между `?.`, `?:` и `!!`, отличить `lateinit` от `by lazy`.

## Зачем это вам

Почти каждое падение «NullPointerException» на ревью — это `!!` или поле, которое кто-то забыл заполнить. Дальше в курсе лямбды сами бывают `null`: `(() -> Unit)?`. Если `?.` и `?:` не на автомате, nullable-лямбды будут путать.

Урок — не про синтаксис с нуля: вы Kotlin уже писали. Здесь собрано то, что спрашивают на скрининге первым.

## Теория

**val и var.** `val` — ссылка, которую нельзя переназначить. `var` — можно. `val list = mutableListOf(1)` всё равно разрешает `list.add(2)`: неизменна ссылка, не содержимое. По умолчанию пишут `val`, `var` берут, когда значение меняется по делу.

**Типы.** Kotlin выводит тип сам: `val port = 80` — `Int`. Тип пишут явно у публичных функций и свойств, где вывод скрывает намерение. Числа не приводятся неявно: `val x: Long = 1` ругнётся, нужен `1L` или `.toLong()`. `String` неизменяема, шаблон: `"IP: $ip, порт ${port + 1}"`.

**Null-safety.** `String` не бывает `null`. `String?` бывает. Компилятор не даст вызвать метод у `String?` напрямую.

- `s?.length` — безопасный вызов: если `s == null`, результат `null` (тип `Int?`).
- `s?.length ?: 0` — Элвис: значение справа, если слева `null`.
- `s!!` — «я клянусь, что не `null`»: если соврали, исключение. В коде приложения `!!` почти всегда запах.
- `if (s != null) { s.length }` — умное приведение: внутри блока `s` уже `String`. Работает для `val` и локальных переменных, не для изменяемых свойств класса, которые мог поменять другой поток.
- `requireNotNull(x) { "нет IP" }` и `checkNotNull` — когда `null` означает ошибку программиста, и вы хотите внятное сообщение.

**lateinit.** `lateinit var adapter: Adapter` обещает: значение придёт до первого чтения (в `onCreate`, в тесте `@Before`). Только для `var` и не для примитивов. Прочитали раньше — `UninitializedPropertyAccessException`. Проверка: `::adapter.isInitialized`. На Android с ViewBinding и Hilt `lateinit` встречается постоянно. Если можно передать значение в конструктор, лучше конструктор.

**by lazy.** `val config by lazy { loadConfig() }` — `val`, вычисляется при первом чтении и запоминается. По умолчанию потокобезопасно. Подходит для дорогого объекта, который может не понадобиться.

| | lateinit var | by lazy |
| --- | --- | --- |
| Кто заполняет | вы, снаружи, позже | лямбда, при первом чтении |
| `val` или `var` | `var` | `val` |
| Если не заполнили | исключение при чтении | не бывает: лямбда сама |

## Разбор на примере

Пульт хранит IP станции, пока пользователь не ввёл его:

```kotlin
class RemoteState {
    var ip: String? = null

    fun baseUrl(): String? = ip?.let { "http://$it" }
    fun baseUrlOrDefault(): String = baseUrl() ?: "http://192.168.10.1"
}
```

`ip` — `String?`, потому что «не ввели» — нормальное состояние. `?.let { ... }` вернёт `null`, если `ip == null`, иначе строку (про `let` — [урок 09](09-scope-functions.md)). Элвис даёт запасной адрес. Ни одного `!!`.

Плохой вариант: `val url = "http://" + ip!!`. Пока поле не заполнено, приложение упадёт на кнопке.

## Упражнения

Руками, в `Scratch.kt` или в REPL IntelliJ. Ответы напишите комментарием рядом.

1. `val name: String? = null`. Что напечатают `name?.length`, `name?.length ?: -1`, `name.orEmpty().length`? Проверьте.
2. Перепишите `val n = if (s != null) s.length else 0` одной строкой через Элвис.
3. Объявите `lateinit var token: String` в классе и прочитайте до присвоения. Какое исключение? Теперь добавьте проверку `::token.isInitialized`.
4. Сделайте `val big by lazy { println("считаю"); 42 }`. Дважды прочитайте `big`. Сколько раз напечатается «считаю»?
5. Вслух: когда `!!` допустим? (Подсказка: почти никогда в продакшн-коде; тест и `main` из учебника — другое.)

### Самопроверка

- `val` и `var` вы объясняете на примере списка.
- Для каждой строки из упражнения 1 вы называете тип результата.

## Типичные ошибки

- `!!` «чтобы собралось».
- `lateinit` для значения, которое можно передать в конструктор.
- Путать `?:` и `?.`: первый подставляет значение, второй продолжает цепочку.
- `var` везде «на всякий случай».
- Ждать, что `lazy` перечитает значение после изменения источника: он вычисляется один раз.
