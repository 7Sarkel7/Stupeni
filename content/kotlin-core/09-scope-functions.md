## Цель

Выбрать между `let`, `run`, `apply`, `also` и `with` по двум вопросам: как объект виден внутри (`it` или `this`) и что вернётся (объект или результат лямбды).

## Зачем это вам

`?.let { }` стоит рядом с каждым nullable (тип, значение которого может быть `null`). `apply { }` — в каждой инициализации `Intent`, `Bundle`, `Paint`. `also { log(it) }` — в отладке (отладка, дебаг — поиск причины ошибки: остановка программы, просмотр значений, логов) цепочек. Это тоже лямбды, только особой формы: [функции с получателем](04-function-types.md), у которых внутри `this`.

## Теория

Все пять — `inline`-функции, принимающие лямбду. Различия — в таблице.

| Функция | Внутри объект как | Возвращает | Типичное применение |
| --- | --- | --- | --- |
| `let` | `it` | результат лямбды | nullable-цепочки, преобразование |
| `run` | `this` | результат лямбды | вычислить что-то с объектом |
| `with(obj)` | `this` | результат лямбды | то же, но объект — аргумент, не получатель |
| `apply` | `this` | сам объект | настроить объект после создания |
| `also` | `it` | сам объект | побочное действие: лог (журнал, куда программа записывает, что делает), проверка |

**Как выбрать.**

- Нужно настроить и вернуть объект: `apply`.
- Нужно сделать побочное действие и пойти дальше по цепочке: `also`.
- Нужно превратить объект в другое значение: `let` (если удобен `it`) или `run` (если удобен `this`).
- Нужно вызвать несколько методов одного уже существующего объекта: `with`.

**let и nullable.**

```kotlin
val length = name?.let { it.trim().length }          // Int?
ip?.let { connect(it) }                              // вызывается только если ip != null
val url = ip?.let { "http://$it" } ?: "http://192.168.10.1"
```

Внутри блока `it` уже не `null`. Разница с `if (ip != null)`: `let` работает для изменяемых полей (берёт копию) и встраивается в выражение.

**apply.**

```kotlin
val intent = Intent(context, DetailActivity::class.java).apply {
    putExtra("id", id)
    flags = Intent.FLAG_ACTIVITY_NEW_TASK
}
```

Внутри лямбды `this` — `Intent`, поэтому `putExtra` без префикса. Результат — тот же `Intent`.

**also.**

```kotlin
val files = loadFiles()
    .also { println("загрузили ${it.size}") }
    .filter { it.isNew }
```

Лог не меняет цепочку. `also` удобно ставить в любое место и убирать.

**run и with.**

```kotlin
val summary = settings.run { "$host:$port (retries=$retries)" }
val text = with(settings) { "$host:$port" }
```

`run` — вызов метода на объекте, `with` — функция, куда объект передан аргументом. Есть и `run { }` без получателя: блок для вычисления выражения.

**Читаемость.** Самое опасное — вложенность. Два `let` друг в друге с одинаковым `it` ломают понимание:

```kotlin
a?.let { x -> b?.let { y -> use(x, y) } }   // имена спасают
```

Если вложение глубже двух, лучше обычный `if` и локальные переменные. Scope-функции ради «красоты» — стилевая ошибка, которую ловят на ревью (проверка вашего кода другим человеком до того, как изменения попадут в проект).

**Побочные эффекты.** `apply` и `also` возвращают сам объект, поэтому ими удобно настраивать и логировать. `let` и `run` — когда нужен другой результат. Если вы возвращаете `Unit` из `let` и игнорируете, `if` тоже подойдёт.

**takeIf / takeUnless.** Родственники: `value.takeIf { it > 0 }` — значение или `null`. В паре с `?.let`: `input.toIntOrNull()?.takeIf { it in 1..65535 }`.

## Разбор на примере

Порт, который пользователь ввёл в поле:

```kotlin
fun parsePort(raw: String?): Int? =
    raw
        ?.trim()
        ?.toIntOrNull()
        ?.takeIf { it in 1..65_535 }
```

Цепочка из четырёх шагов, каждый возвращает `null`, если дальше идти некуда. Нет ни одного `if`, нет `!!`.

Построение запроса в `OkHttp`-стиле:

```kotlin
val request = Request.Builder()
    .url(url)
    .apply { token?.let { header("Authorization", "Bearer $it") } }
    .build()
```

`apply` вставил условный шаг в цепочку билдера, `let` внутри проверил `token`.

## Упражнения

1. Перепишите `if (x != null) println(x.length)` через `?.let`.
2. Дан `class Config { var host = ""; var port = 0 }`. Создайте экземпляр и заполните через `apply`.
3. Вставьте `also { println(it) }` в середину цепочки `filter` и `map`. Уберите, цепочка не должна измениться.
4. Объясните, почему `val n = name.let { it.length }` и `val n = name.run { length }` дают одно и то же.
5. Какой из пяти вернёт `Unit`, если последняя строка лямбды — `println`? (`let`, `run`, `with`. `apply` и `also` вернут объект.)
6. Напишите `parsePort` из разбора без `takeIf` и сравните читаемость.
7. Найдите в проекте с Compose три места, где используются эти функции, и подпишите каждое: `it` или `this`, объект или результат.

### Самопроверка

- По таблице без подглядывания называете возвращаемое значение и `it`/`this` для каждой.
- Объясняете, почему `?.let` безопаснее `!!`.

## Типичные ошибки

- `apply` там, где нужен результат: получаете объект вместо числа.
- `let` без `?.` на не-nullable «для красоты».
- Вложенные `it`.
- Цепочка из пяти scope-функций на одной строке.
- Менять объект в `also`, ожидая, что цепочка изменится: он возвращает тот же объект.
- Забыть, что внутри `apply` `this` затеняет внешний `this` класса; используйте `this@ИмяКласса`.
