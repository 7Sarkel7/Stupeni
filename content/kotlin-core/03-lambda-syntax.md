## Цель

Прочитать и написать лямбду любой формы: с параметрами, с `it`, с несколькими строками, как последний аргумент вне скобок. Понять, что лямбда — это обычное значение, которое лежит в переменной и ждёт вызова.

## Зачем это вам

Лямбды — слабое место, а они везде: `onClick = { ... }`, `list.filter { ... }`, `viewModelScope.launch { ... }`, `Button(onClick = onSend)`, `remember { ... }`. Если лямбда выглядит магией, Compose и корутины тоже будут магией. Этот урок убирает магию: лямбда — просто кусок кода, завёрнутый в значение.

## Теория

**Лямбда — функция без имени.** Обычная функция:

```kotlin
fun double(x: Int): Int = x * 2
```

Та же логика лямбдой, положенной в переменную:

```kotlin
val double = { x: Int -> x * 2 }
println(double(21)) // 42
```

Разбор синтаксиса: фигурные скобки ограничивают лямбду; слева от стрелки `->` параметры (с типами, если Kotlin не может вывести их сам); справа тело. **Результат лямбды — значение последнего выражения**, слова `return` внутри нет.

```kotlin
val greet = { name: String ->
    val upper = name.uppercase()
    "Привет, $upper"   // последнее выражение — результат
}
```

**Вызов.** Лямбду вызывают как функцию: `greet("Никита")`. Явная запись — `greet.invoke("Никита")`. Это одно и то же; `invoke` пригодится в [уроке про nullable-лямбды](05-nullable-lambdas.md).

**Без параметров.** `val ping = { println("ping") }` — стрелка не нужна.

**Тип параметра можно не писать, если он известен из контекста.** `listOf(1, 2, 3).map { x -> x * 2 }`: Kotlin знает, что `map` отдаёт элементы `Int`.

**it.** Если у лямбды ровно один параметр и тип известен из контекста, его можно не называть: он будет `it`.

```kotlin
listOf(1, 2, 3).map { it * 2 }   // [2, 4, 6]
```

Когда `it` хорош: короткая лямбда на одну мысль. Когда лучше имя: вложенные лямбды (два `it` путают) или тело длиннее двух строк. `{ device -> device.ip }` читается лучше, чем `{ it.ip }`, если рядом ещё одна лямбда.

**Неиспользуемый параметр.** `{ _, value -> value }` — подчёркивание говорит: этот параметр не нужен. Типичный случай — `Map.forEach { (key, value) -> ... }` и `mapValues { (_, v) -> v.size }`.

**Trailing lambda.** Если последний параметр функции — функция, лямбду можно вынести за скобки:

```kotlin
list.filter({ it > 1 })   // правильно, но так не пишут
list.filter { it > 1 }    // идиома: «хвостовая лямбда»
```

Если лямбда — единственный аргумент, скобки опускаются совсем. Если есть другие аргументы, они остаются в скобках, лямбда идёт после:

```kotlin
repeat(3) { println("раз") }
Button(onClick = { send() }) { Text("Отправить") }
```

Во втором примере `onClick` назван и лежит в скобках, а `{ Text("Отправить") }` — последний параметр `content`, вынесенный наружу. Именно поэтому Compose выглядит как вложенные блоки: это обычные вызовы с хвостовой лямбдой.

**Безымянная функция и ссылка на функцию.** Лямбду можно заменить ссылкой, если функция уже есть: `list.map(::double)`, `names.forEach(::println)`. Подробнее в [следующем уроке](04-function-types.md).

**Return из лямбды.** Голый `return` внутри лямбды `forEach` вернёт из **внешней** функции (это работает потому, что `forEach` — inline, [урок 06](06-capture-inline.md)). Чтобы выйти только из лямбды, пишут метку: `return@forEach`. Для лямбды после `map`: `return@map value`.

```kotlin
fun firstEven(list: List<Int>): Int? {
    list.forEach {
        if (it % 2 == 0) return it   // выйдет из firstEven
    }
    return null
}
```

## Разбор на примере

Кнопка «Обновить показания» в пульте. Раньше слушатель писали классом, теперь лямбдой:

```kotlin
// 1. Полная форма
button.setOnClickListener({ view -> sendShow() })
// 2. Параметр не нужен: подчёркивание
button.setOnClickListener({ _ -> sendShow() })
// 3. Лямбда последняя — выносим за скобки
button.setOnClickListener() { sendShow() }
// 4. Единственный аргумент — скобки не нужны
button.setOnClickListener { sendShow() }
```

Четыре записи — одно и то же. `OnClickListener` — интерфейс с одним методом, поэтому Kotlin позволяет передать вместо него лямбду (SAM-преобразование). Вторая половина урока: то же, но в Compose.

```kotlin
Button(onClick = { sendShow() }) { Text("Показать") }
```

`onClick` — параметр типа `() -> Unit`. Вы передали лямбду, которая ничего не принимает и ничего не возвращает. `Text("Показать")` — тоже лямбда, `@Composable () -> Unit`.

### Самопроверка

- Вслух: лямбда — это значение или вызов? (Значение. Вызов — когда поставили скобки.)
- Знаете, что значит `{ }` без стрелки и без параметров.
- Объясняете, откуда берётся `it` и почему он не всегда хорош.

## Типичные ошибки

- Написать `return` внутри лямбды `map` и удивиться, что вышли из функции целиком. Нужна метка.
- Думать, что `{ println("a") }` внутри `val x = ...` выведет `a` сразу. Нет: пока не вызвали `x()`, ничего не напечатается.
- Вложенные `it` в двух лямбдах: внутренний затеняет внешний.
- Стрелка там, где параметров нет: `{ -> ... }` законно, но лишне.
