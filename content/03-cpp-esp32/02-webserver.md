# Плата как сайт

**Модуль:** 03. C++ и ESP32  
**Время:** около 30 минут  
**Дальше:** [Слой stationDo](03-api-actions.md)

## Цель

Поднять на станции `GET /v1/reading`, открыть его с ноутбука по `http://192.168.10.1/v1/reading` и только после этого писать клиент на Kotlin. Отличать «сервер не создан» от «сервер не обслуживают в loop».

## Зачем это вам

Телефон — плохой первый клиент: у него cleartext, корутины и введённый руками IP. Браузер на ноутбуке в сети SoftAP убирает всё это. Если страница не открывается, прошивка ещё не готова к пульту. Этот порядок уже был в отладке; здесь вы собираете сам сервер.

Локальный API слушает порт 80, без TLS. Порт 443 и сертификат на точку доступа платы не добавляют первой проверке ничего, кроме часа возни со временем и памятью.

## Теория

Один объект сервера на всю жизнь скетча, не локальная переменная `loop`: иначе вы каждый проход создаёте и убиваете слушателя.

```cpp
#include <WebServer.h>

WebServer server(80);

void handleApiStatus() {
  server.send(200, "text/plain", "OK fw:0.9.0 board:esp32s3_dev");
}

void setup() {
  Serial.begin(115200);
  server.on("/v1/reading", HTTP_GET, handleApiStatus);
  server.begin();
}

void loop() {
  server.handleClient();
}
```

`server.on` связывает метод и путь с функцией. Путь с ведущим `/`. `send` задаёт код, тип и тело. Для статуса тип `text/plain`. Строка нарочно человеческая: глазами видно `OK`, а разбор обновления прошивки ищет подстроки `fw:` и `board:`. Не отдавайте сюда HTML-страницу и не отдавайте прошивку целиком.

Пока карты нет, маршруты, которым карта нужна, отвечают `503` и коротким текстом `SD unavailable`. Не отвечайте `200`, чтобы пульт «не расстраивался». Честный код — это и есть интерфейс.

Несколько маршрутов — несколько `on`. Не один `if` в `setup`, который «выберет обработчик навсегда». Выбор происходит на каждый запрос внутри `handleClient`.

`Retrofit`, `@GET` и Ktor на плате не живут. Это клиенты и серверы других сред. На ESP в этой архитектуре — `WebServer` из ядра Arduino. Пульт может быть на Retrofit или OkHttp, плате всё равно: она видит HTTP.

Полезный минимум, который уже можно проверить без кнопки:

```bash
curl -sS -m 3 http://192.168.10.1/v1/reading
```

Ожидание: строка с `OK` и версией. `connection refused` — `begin` не вызывался или порт другой. Таймаут — не та сеть, радио не поднято, либо `loop` не доходит до `handleClient`.

Имя точки доступа лучше делать уникальным по хвосту MAC, иначе два станции в комнате неразличимы:

```cpp
uint8_t mac[6];
esp_read_mac(mac, ESP_MAC_WIFI_STA);
snprintf(apSsid, sizeof(apSsid), "METEO-%02X%02X", mac[4], mac[5]);
```

Телефон и ноутбук подключаются к `METEO-A1B2`, не к чужой станции с тем же именем по умолчанию. В этом учебном проекте шлюз SoftAP задаёте сами: `192.168.10.1`. Если вы его меняли в коде, `curl` идёт на новый адрес, а не «на тот, что в уроке».

Обработчик статуса не трогает карту и не ходит в облако. Он должен отвечать, даже когда всё остальное сломано. Иначе у вас нет нижней ступеньки отладки.

## Разбор на примере

Вечер без Android Studio:

1. Прошили скетч со status.
2. Подключили ноутбук к `METEO-….`.
3. Открыли `http://192.168.10.1/v1/reading`.
4. Увидели `OK fw:... board:esp32s3_dev`.
5. Закоммитили этот скетч на `main`. Это зелёная точка из урока про git.

Дальше нарочно опечатайтесь: зарегистрируйте `"v1/reading"` без слэша, прошейте, обновите браузер. Увидите отказ, не `OK`. Верните слэш. Одна такая проверка учит сильнее абзаца.

Не добавляйте в этот вечер заливку файла. Status, который стабильно открывается, ценнее наполовину сделанного upload, из-за которого вы вынули `handleClient`.

## Упражнения

1. `server` создан внутри `loop` перед `begin` и `handleClient`. Почему «я же вызываю оба» всё равно неверная конструкция?
2. Какой код и какое тело вернуть, если список файлов невозможен без карты, а карты нет? Почему `200` и пустой список здесь хуже?
3. Пульт будет на OkHttp. Меняется ли из-за этого регистрация маршрута на плате?

### Ориентир для самопроверки

Сначала запишите ответы своими словами. Короткий ключ к этим вопросам — [02-webserver.md](../hints/02-webserver.md). Откройте его после своей попытки и отметьте расхождения. Дословно в тетрадь ключ не переписывайте. К самостоятельной работе модуля этот ключ не относится: там решения в репозитории нет.

## Типичные ошибки

- Забыть `handleClient` и искать ошибку в кабеле.
- Путь без ведущего слэша.
- Отдать статус как `application/json`, а тело оставить текстом `OK fw:...`, или наоборот.
- Разбирать журнал внутри обработчика status «заодно».
- Сразу идти в облачный WebSocket, не сохранив локальный status.

## Чеклист

- [ ] `WebServer` один и живёт не на стеке `loop`.
- [ ] `GET /v1/reading` открывается в браузере на SoftAP.
- [ ] Тело короткое, в нём есть версия прошивки.
- [ ] Зависимые от карты маршруты умеют честный 503.
- [ ] Этот скетч отмечен как известная рабочая точка.
