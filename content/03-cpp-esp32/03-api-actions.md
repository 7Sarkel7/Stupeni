# Слой stationDo

**Модуль:** 03. C++ и ESP32  
**Время:** около 35 минут  
**Дальше:** [Лестница транспортов](04-ladder.md)

## Цель

Ввести одно действие показа файла: проверка пути, флаг для `loop`, ответ HTTP. Оформить действия так, чтобы и кнопка, и будущее облако вызывали одну функцию. Не декодировать GIF в обработчике запроса.

## Зачем это вам

Без этого слоя каждый новый транспорт копирует «ну как-нибудь покажи». Через месяц локальная кнопка умеет проверять путь, облако — нет, голос вызывает третью копию на Python. Баг чинится в одном месте и остаётся в двух. `stationDo*` — меню станца. Транспорты только приносят имя команды и аргументы.

Контракт функции один на всё меню:

```cpp
bool stationDoPublish(const String& pathIn, String& err);
bool stationDoIdle(String& err);
```

`true` — действие принято. `false` — в `err` короткое слово (`empty`, `missing`), которое HTTP отдаст телом 400. Облако позже положит ту же строку в JSON подтверждения. Человек увидит её в Toast.

## Теория

Объявления живут в одном заголовке, например `api_actions.h`. Это оглавление, а не место для декодера.

Показ:

```cpp
bool stationDoPublish(const String& pathIn, String& err) {
  if (pathIn.isEmpty()) {
    err = "empty";
    return false;
  }
  if (!sdExists(pathIn)) {
    err = "missing";
    return false;
  }
  g_gifPath = pathIn;
  g_pendingGifPlayback = true;
  return true;
}
```

`sdExists` здесь — ваша проверка на карте, имя не важно. Важно, что отказ происходит до флага. Чёрный экран «мы приняли команду» хуже явного `missing`.

Флаг `g_pendingGifPlayback` читает цикл отрисовки. HTTP-обработчик до экрана не дотрагивается:

```cpp
void handleApiDisplay() {
  String err;
  if (!stationDoPublish(server.arg("path"), err)) {
    server.send(400, "text/plain", err);
    return;
  }
  server.send(200, "text/plain", "OK");
}
```

Стоп снимает показ и не перезагружает чип:

```cpp
bool stationDoIdle(String& err) {
  g_pendingGifPlayback = false;
  (void)err;
  return true;
}
```

Перезагрузка — отдельная, редкая сервисная команда, если она вообще нужна. Жест «стоп» на пульте ею не является. Гасить `WiFi.mode(WIFI_OFF)` внутри стопа тоже нельзя: вы лечите ролик отключением единственного канала, по которому придёт следующая команда.

Скорость и звук, когда дойдёте, ложатся рядом такими же функциями. Скорость — множитель паузы между кадрами или пропуск кадров, не перекодирование GIF на плате в обработчике. Звук — путь к файлу на той же карте, не `MediaPlayer` из Android, его на ESP нет.

Команда из облака, когда она появится, выглядит как развилка по имени:

```cpp
if (cmd == "display") {
  ok = stationDoPublish(path, err);
} else if (cmd == "stop") {
  ok = stationDoIdle(err);
} else {
  err = "unknown";
  ok = false;
}
```

Неизвестное имя — отказ, не `eval`. Имена совпадают с пультом: `display`, не `show`.

Путь `photos/sunset.gif` — на карте станца. `https://...` этим действием не скачивают. Скачивание по URL, если оно нужно для обновления прошивки, — другой маршрут и другая функция. Иначе display начнёт ходить в интернет из обработчика и снова заблокирует `loop`.

Пока действия два, заголовок легко держать в голове. Не плодите десяток команд «на вырост» пустыми заглушками, которые отвечают `true`. Ложный успех хуже отсутствия маршрута.

Поток данных такой:

```text
кнопка или облако
        │  path, имя команды
        ▼
   stationDoPublish / stationDoIdle
        │  флаг и путь, либо err
        ▼
   loop рисует или гасит кадр
```

Стрелка назад, в телефон, — только код HTTP или ack. Кадры по BLE и по сокету на телефон не едут. Экран станца рядом с платой.

## Разбор на примере

Вечер одной команды.

1. В заголовке две функции.
2. Реализация проверяет путь и ставит флаг.
3. `POST /api/display` с `path=photos/sunset.gif` даёт `200`, если файл есть.
4. Тот же вызов с пустым полем даёт `400` и `empty`.
5. `POST /v1/idle` гасит флаг, ролик останавливается, Wi-Fi жив.
6. В Serial одна строка на отказ и одна на принятый путь. Не печать каждого кадра.

Проверка с ноутбука, пульт ещё может быть вчерашним:

```bash
curl -sS -m 3 -X POST http://192.168.10.1/api/display \
  --data-urlencode "path=photos/sunset.gif"
curl -sS -m 3 -X POST http://192.168.10.1/v1/idle
```

Если первый `curl` вернул `OK`, а экран чёрный, вы не переписываете `stationDoPublish` вслепую. Смотрите, кто читает флаг. Если никто, действие честно отработало, отрисовки ещё нет. Это дырка в `loop`, не в HTTP.

Когда оба `curl` скучны и предсказуемы, подключайте кнопку из модуля 02. Она обязана послать то же поле `path`. Если кнопка шлёт JSON, а `curl` шлёт форму, у вас два клиента разных API. Оставьте форму для LAN.

### Ориентир для самопроверки

Сначала запишите ответы своими словами. Короткий ключ к этим вопросам — [03-api-actions.md](../hints/03-api-actions.md). Откройте его после своей попытки и отметьте расхождения. Дословно в тетрадь ключ не переписывайте. К самостоятельной работе модуля этот ключ не относится: там решения в репозитории нет.

## Типичные ошибки

- Две реализации показа: одна в HTTP, вторая заранее скопирована в файл облака.
- Отвечать `200` до проверки, есть ли файл.
- Стоп через перезагрузку.
- Принимать любое имя команды строкой из модели.
- Тащить в `stationDo*` типы Android (`Context`, `Toast`). У платы их нет. Текст ошибки — `String err`.
