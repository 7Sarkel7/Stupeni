## Цель

Собрать цепочку «экран читает базу, сеть пишет в базу, настройки лежат в DataStore» и свернуть очередь исходящих перед отправкой.

## Зачем это вам

Пульт станца ходил в локальный HTTP через OkHttp и держал адрес на диске. Продуктовый экран почти всегда добавляет три вещи: описание API отдельным интерфейсом, локальную таблицу как источник правды и маленький ключ настроек. На собеседовании это называют одним вопросом «как у вас устроен офлайн».

Страницы: [Retrofit](https://square.github.io/retrofit/), [OkHttp](https://square.github.io/okhttp/), [Room](https://developer.android.com/training/data-storage/room), [DataStore](https://developer.android.com/topic/libraries/architecture/datastore), [слой данных](https://developer.android.com/topic/architecture/data-layer).

## Теория

OkHttp делает вызов. Таймауты соединения, чтения и записи задают в `OkHttpClient.Builder` явно. Клиент без таймаута может висеть, пока система сама не оборвёт сокет, и человек смотрит на вечный прогресс. Один клиент на процесс. Логирующее тело запроса включают в отладочной сборке и выключают в релизе: в лог попадают тексты заметок.

Retrofit описывает метод: путь, глагол, тело. Suspend-функция main-safe относительно потока вызова, сам сокет при этом блокирует пул OkHttp, не главный поток. Разбор JSON, который не совпал с типом, приходит ошибкой. Её превращают в фразу до кадра. Коды `400` и `401` не повторяют. Обрыв и `503` повторять можно, с растущей паузой и потолком.

Room хранит строки. Таблица — класс с `@Entity`, доступ — интерфейс DAO, база — абстрактный класс с версией. Для одной версии без смены схемы миграция не нужна, но версию всё равно пишут, а схему экспортируют так, как просит документация Room на день проекта. Список для UI — `Flow` из DAO. Каждый `insert` и `update` будит сборщиков. Разовый `List` после кнопки «обновить» врёт, как только строка изменилась из фона.

Suspend-методы DAO вызывают с любого диспетчера, Room сам уходит с главного. Ручной доступ к файлу базы в обход DAO этот договор ломает.

Картинки в столбцы таблицы не кладут. В столбце путь или имя файла. Большой блоб раздувает запрос списка и легко попадает на главный поток при неосторожном чтении.

DataStore Preferences хранит маленькие настройки: имя, час напоминания, последний успешный `since`. Это не таблица заметок. `SharedPreferences.commit()` на главном потоке — старый способ, в новом коде берут DataStore. Чтение наружу — `Flow`, запись — suspend. Файл DataStore в git не коммитят, если в нём вдруг оказался токен с устройства.

Источник правды для списка — база. Сеть не рисует кадр напрямую. Успешный ответ кладут в Room в той же корутине, на IO, и экран узнаёт об этом из `Flow`. Так кадр не расходится с тем, что переживёт убийство процесса.

Очередь исходящих нужна, когда правка случилась без сети. Каждая правка дописывает операцию `CREATE`, `UPDATE` или `DELETE` с растущей ревизией. Перед HTTP очередь сворачивают, иначе на сервер уедет «создал, переименовал, удалил» тремя запросами, а человека уже нет.

Правила свёртки, их и проверяет лабораторная:

- одна ячейка на локальный id, в ответе порядок первого появления;
- ревизия не меньше 1, внутри id строго растёт, пустой id — ошибка;
- CREATE и потом UPDATE остаются CREATE с новой ревизией;
- CREATE и потом DELETE исчезают: сервер эту запись не видел;
- UPDATE и потом UPDATE оставляет последний UPDATE;
- UPDATE и потом DELETE становится DELETE;
- DELETE и потом CREATE становится CREATE;
- второй CREATE, второй DELETE и UPDATE после DELETE — ошибка вызова.

Домашняя работа этого урока очередь ещё не обязана слать на ваш сервер. Она обязана научить цепочку «сеть → база → экран» на чужом маленьком JSON. Свёртку сдают лабораторной, в капстоуне её переносят в `smena` своими именами.

## Разбор на примере

`GET` одного объекта с публичного учебного JSON, без авторизации, кладёт в Room строку: внешний id и заголовок. DAO отдаёт `Flow`. Экран собирает его в снимок. Время последнего успеха пишется в DataStore. Пока сети нет, список показывает то, что уже лежит в базе, а не пустой экран-ошибку. Ошибка сети — отдельная фраза, если базы ещё нет.

Это ещё не журнал смены. Нет фото, нет batch, нет конфликта. Есть шов, без которого журнал развалится на первой вехе.

### Самопроверка

- CREATE+DELETE не остаётся в списке на отправку.
- Таймауты вы можете назвать вслух, даже если цифры возьмёте свои.
- Намёк [solutions/hint-outbox.md](solutions/hint-outbox.md) закрыт.

## Типичные ошибки

- Рисовать список из ответа Retrofit и не писать базу.
- Хранить тысячи заметок в DataStore.
- Класть JPEG в столбец Room.
- Повторять `POST` на `400`.
- Отправлять сырую историю кликов без свёртки.
