# Капстоун: журнал «Смена»

**Модуль:** капстоун трека найма Android  
**Уровень:** J, веха про второй транспорт в спеке помечена **M**  
**Время:** около 35 минут на этот урок, дальше несколько недель вечеров  
**Спека:** [capstone/SPEC.md](capstone/SPEC.md)  
**Намёк:** [solutions/hint-capstone.md](solutions/hint-capstone.md)  
**Дальше:** свой репозиторий, не следующий модуль станции

## Цель

Понять, зачем журнал смены, и завести свой репозиторий до первой записи в базе.

## Зачем это вам

Домашние работы разобрали стек по слоям в `hire-scratch`. Нанимающий открывает один репозиторий, где слои снова вместе и где виден человек на объекте: место, текст, фото, авиарежим, очередь, фон, уведомление. Спека [Смена](capstone/SPEC.md) для этого и написана.

Журнал выбран потому, что им пользуются в конце реального дня. Подвал и монтаж часто без связи. Запись, которая ждёт сеть, не записывают. Список дел и трекер привычек на GitHub выглядят как упражнение. Учёт расходов слабо показывает очередь и фото узла. Поиск устройств в локальной сети не собирает Room, пуш и WorkManager в один сценарий. Лампа [DeskNode](../career/capstone/SPEC.md) остаётся капстоуном карьерного трека про плату. Метеостанцию «Поле» в этот репозиторий не переносят.

Готового приложения в Ступенях нет. Каркас имён без реализации лежит в [capstone/skeleton](capstone/skeleton/README.md). Если положить сюда рабочую «Смену», на защите нечего будет ответить на вопрос «покажите, где свернётся очередь».

## Теория

Репозиторий новый, публичный, имя вроде `smena`. Код из `hire-scratch` не копируют: приёмы те же, типы называют заново.

Порядок вех M0–M7 совпадает с отладкой слоями. Сначала пустой репозиторий и зелёный тест-заглушка идентификатора. Затем запись без сети. Затем фото и настройки. Затем контракт, который повторяет `curl`. Затем уникальный работник. Затем MockK, Turbine, кадр и CI. Затем канал, локальное напоминание и один пуш-транспорт. В конце README на двух языках и один pull request.

Перепрыгнуть на пуш, пока запись не жива в авиарежиме, можно. Починить такой прыжок трудно: неясно, молчит шторка или молчит база.

Номера библиотек берут в день M0 со страниц, на которые ссылается спека. Урок их не замораживает.

## Разбор на примере

Вечер M0. Пустой Android-проект открывается. README говорит, чего ещё нет: нет записи, нет сервера, нет магазина. В ограничениях сразу написано, что установки на объекте нет. Дата, к которой вы хотите закрыть M7, стоит в тексте, чтобы вечер не расползался на второй продукт.

Следующий вечер — M1, одна запись. Фото в этот вечер не добавляют.

## Упражнения

1. Прочитайте [capstone/SPEC.md](capstone/SPEC.md) целиком, включая рубрику. Отметьте пункты J, которые пока звучат незнакомо, и вернитесь в урок этого трека, а не в чужой репозиторий «полевого CRM».
2. Заведите публичный репозиторий и закройте M0 так, как она описана в спеке.
3. В черновике резюме добавьте строку «Смена — после M7», без функций, которых ещё нет.
4. Расписание вечеров до M7 держите у себя. Сдвиг недели допустим. Отмена M1 ради иконки уведомления — нет.

### Самопроверка

- Репозиторий открывается без паролей внутри.
- Вы можете сказать, почему это не список дел и не DeskNode.
- Следующая веха — M1, команда `curl` ещё не обещана.

## Типичные ошибки

- Форкнуть Ступени и положить журнал рядом с уроками.
- Скопировать `hire-scratch` и сменить пакет.
- Начать с карты объекта и аккаунтов.
- Написать в README «production-ready».
- Подключить FCM и RuStore сразу, не показав ни одной записи.
- Ждать, что SPEC содержит исходники. Их нет специально.
