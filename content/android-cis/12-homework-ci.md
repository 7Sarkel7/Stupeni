# Самостоятельная: зелёный workflow

**Модуль:** A6. Найм Android, стек СНГ  
**Уровень:** J  
**Время:** один вечер в `hire-scratch`  
**Лаборатория:** нет  
**Намёк:** [solutions/hint-ci.md](solutions/hint-ci.md)  
**Дальше:** [Push: FCM и RuStore](13-push.md)

## Цель

Получить зелёный прогон юнит-тестов на GitHub и один красный прогон, который вы сами починили.

## Зачем это вам

Файл, который ни разу не запускался, на собеседовании рассыпается на вопросе «покажите последний build». Красный прогон, который вы починили, как раз показывает, что workflow связан с тестом, а не с пустой командой.

## Теория

Репозиторий `hire-scratch` должен быть на GitHub, иначе Actions негде включить. Если он был только локальным, заведите удалённый и не выкладывайте `local.properties`.

Секреты не создают. В этом вечере им нечего хранить.

## Разбор на примере

Сначала зелёная база: тесты ViewModel проходят в CI. Затем в отдельном коммите ломаете ожидание заголовка на заведомо неверную строку, пушите, дожидаетесь красного, возвращаете верное ожидание следующим коммитом. В истории видно оба коммита. В README команда та же, что в workflow.

## Упражнения

- [ ] Workflow запускается на push и на pull request.
- [ ] JDK в файле совпадает с README.
- [ ] Шаг гоняет юнит-тесты, не только сборку APK.
- [ ] Эмулятора в файле нет.
- [ ] Секретов и keystore в репозитории нет.
- [ ] Версии `checkout` и `setup-java` вы сверили с Marketplace в день коммита.
- [ ] Был красный прогон из-за сломанного теста и следующий зелёный.
- [ ] Ссылка на зелёный прогон записана у вас в README.

### Рубрика

| Часть | 0 | 1 | 2 |
| --- | --- | --- | --- |
| Запуск | файла нет или он не стартовал | стартует только локально через `act` или только на одном событии | push и pull request, прогон виден на GitHub |
| Тесты | шаг собирает проект и не запускает тесты | тесты есть, команда в README другая | команда в README и в шаге одна, падает именно тест ViewModel |
| Секреты | токен или keystore в git | секретов нет, JDK не записан | секретов нет, JDK совпадает |
| Честность | скопирован workflow Ступеней или чужой Android-шаблон без чтения | намёк открыт сразу | файл собран по шагам документации |

Ноль по любой строке — к пушам рано.

## Типичные ошибки

- Закоммитить `local.properties`.
- Отключить шаг после первого красного креста.
- Указать JDK 11, потому что так было в старой статье, и не заметить, что проект им не собирается.

## Чеклист

- [ ] На GitHub есть зелёный прогон.

- [ ] Рубрика без нулей.
- [ ] `build-apk.yml` Ступеней не скопирован.
