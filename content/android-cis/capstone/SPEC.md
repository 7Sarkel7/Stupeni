# Смена — спецификация капстоуна

**Уровень:** J закрывает проект. Строка **M** в рубрике не нужна для отклика.  
**Где делать:** новый публичный репозиторий, имя вроде `smena`. Не форк Ступеней, не каталог этого репозитория, не репозиторий DeskNode и не `hire-scratch`.  
**Чего здесь нет:** исходников экрана, базы, сервера и «правильного» README. Это задание. Каркас имён — в [skeleton](skeleton/README.md). Намёк словами — в [../solutions/hint-capstone.md](../solutions/hint-capstone.md).

## Почему этот проект

Журнал смены нужен в тот день, когда связь пропадает, а помнить всё равно надо. Подвал, лифтовая шахта, цоколь, удалённый монтаж, склад за металлической стеной: телефон пишет заметку и фото в Room сразу, а на сервер отдаёт их позже, из машины или с офисного Wi-Fi. Напоминание в выбранный час не даёт уехать с пустой головой. Завтра утром запись на месте, а не в чате, который не найти.

На GitHub и в резюме это читается как инструмент для человека на объекте, а не как учебный список дел. Список дел и трекер привычек на собеседовании не отличить от главы про CRUD. Учёт расходов переполнен теми же учебными репозиториями и слабо показывает очередь исходящих. Поиск устройств в локальной сети хорошо тренирует сокет и почти не показывает Room, пуш и WorkManager как один продукт. Лампа DeskNode уже занята [карьерным капстоуном](../../career/capstone/SPEC.md): там локальный HTTP и прошивка. Станц Поле — учебный стенд пульта, его в этот репозиторий не переносят.

«Смена» собирает стек, который спрашивают на Android в РФ и СНГ, в одном сценарии, который можно показать за три минуты: самолётный режим, запись, фото, сеть, уход очереди, уведомление.

## Продукт одной фразой

Человек в конце смены записывает место, что сделано и одно фото. Запись жива без сети. Когда сеть есть и батарея не на нуле, очередь уходит на сервер. В выбранный час телефон напоминает закрыть смену.

## Не делаем

- Аккаунт, OAuth, несколько пользователей, карта, чат, магазин приложений.
- Редактор чертежей и замену журналу производства работ по нормам.
- Список покупок, привычки, вторую лампу, прошивку ESP32.
- CRDT и тихую склейку двух текстов в один.
- Секреты, keystore, сервисный токен RuStore и пароль сервера в git.
- Строку middle и «коммерческое внедрение» на основании этого репозитория.
- Готовый код из `hire-scratch`: приёмы те же, имена и экраны пишете заново.

## Кто пользуется

Один человек, один телефон. Вторая установка может прочитать сервер через тот же контракт, это и есть проверка синхронизации. Роли прораба и заказчика нет.

Место — одна строка, как вы сами подписываете точку: «ось 3 / этаж 2», «щитовая», «квартира 12». Отдельных справочников объектов в J нет.

## Экраны

Jetpack Compose и Material 3. Одна Activity вызывает `setContent`. Номер Compose BOM копируют со [страницы BOM](https://developer.android.com/develop/ui/compose/bom) в день, когда создаёте проект. Рядом в Gradle — дата и ссылка. Карта доков: [Jetpack Compose](https://developer.android.com/develop/ui/compose/documentation), [Material 3](https://developer.android.com/develop/ui/compose/designsystems/material3).

Навигация нового кода — та, которую документация называет текущей на день M1. Точка входа курса: [Navigation 3](https://developer.android.com/guide/navigation/navigation-3). Имя типа сверьте со страницей, в спеку номер библиотеки не замораживается.

Экраны J:

1. Список записей. Пустой список — отдельная фраза «Пока пусто», не ошибка сети. У строки видны место, начало текста, состояние «на телефоне», «на сервере» или «конфликт». Фильтр «ещё не ушло» оставляет только неотправленные и конфликтные.
2. Редактор одной записи: место, текст, не больше одного фото, сохранение. Сохранение в авиарежиме оставляет запись в списке после убийства процесса.
3. Настройки: имя, которое попадёт в README-демо как автор записи, час и минута напоминания. Оба значения переживают перезапуск через DataStore.

Пока идёт сохранение или синхронизация, второе нажатие той же кнопки не создаёт вторую работу.

`minSdk` 26, если нет причины ниже. Версию пишете в README.

## Состояние и потоки

Один снимок экрана наружу как `StateFlow`. Корень маршрута собирает его через `collectAsStateWithLifecycle`. Вниз уходят снимок и события, не сам ViewModel.

- Сеть и база — `Dispatchers.IO`.
- Сжатие JPEG — `Dispatchers.Default`.
- Кадр — главный поток. Сокет, `File`, `BitmapFactory` и `runBlocking` в composable и в `onClick` не живут.
- `viewModelScope` отменяется вместе с экраном. `GlobalScope` нет.

Фото: длинная сторона 1280 пикселей, JPEG качество 80, файл в каталоге приложения, в базе путь или имя файла. Байты картинки в SQLite не кладут. Снимок с камеры после сохранения смотрится правильной стороной: ориентацию из EXIF учитывают до сжатия. Страница, с которой сверяют API: [ExifInterface](https://developer.android.com/reference/androidx/exifinterface/media/ExifInterface).

## Данные на телефоне

Room — источник правды для списка. UI наблюдает `Flow` из DAO, не разовый `List` после кнопки.

Поля записи, которые защищаете на ревью: локальный id, место, текст, `createdAt`, `updatedAt`, монотонная `revision`, состояние синка, необязательный путь фото.

Очередь исходящих — отдельные строки операций `CREATE`, `UPDATE`, `DELETE` с той же `revision`. Перед HTTP очередь сворачивается по правилам лаборатории `collapseOutbox`: CREATE и следующий UPDATE остаются одним CREATE с поздней ревизией; CREATE и DELETE до сервера исчезают; UPDATE и DELETE становятся DELETE; DELETE и новый CREATE становятся CREATE; ревизия внутри id строго растёт. Имена в приложении можете взять свои, правила — эти. Тест на свёртку зелёный без эмулятора.

DataStore Preferences хранит имя, час, минуту, свой `deviceId`, bearer, который пользователь вставил сам, и время последней успешной синхронизации. Файл DataStore в git не коммитится.

## Сеть

Retrofit и OkHttp. Таймауты соединения и чтения записаны в README теми числами, которые стоят в коде. Разумный старт: соединение 10 секунд, чтение 30 секунд, потому что уезжает JPEG. Повтор HTTP — на обрыв и на 503, не на 400 и не на 401. Пауза растёт и имеет потолок.

Контракт JSON. Поля, которых нет в этом разделе, клиент пропускает. Bearer передаётся заголовком `Authorization`. Токен в репозиторий не кладут: в README написано, как его задать локально.

### `POST /v1/batch`

Тело:

```json
{
  "deviceId": "uuid",
  "items": [
    {
      "localId": "uuid",
      "op": "CREATE",
      "revision": 3,
      "place": "ось 3",
      "body": "залили участок",
      "updatedAt": 1710000000000,
      "hasPhoto": true
    }
  ]
}
```

`op` — `CREATE`, `UPDATE` или `DELETE`. Перед телом, если `hasPhoto` истинно, клиент успел выполнить `PUT /v1/photos/{localId}` с телом JPEG (`Content-Type: image/jpeg`). Если PUT не удался, эту запись в batch не кладут и оставляют в очереди.

Успех `200`:

```json
{
  "accepted": ["uuid"],
  "conflicts": [
    {
      "localId": "uuid",
      "serverUpdatedAt": 1710000001000,
      "place": "ось 3",
      "body": "текст с сервера"
    }
  ]
}
```

`accepted` помечают синхронизированными и снимают с очереди. `conflicts` остаются на телефоне в состоянии «конфликт». Две кнопки в редакторе: «оставить мою» поднимает ревизию и возвращает запись в очередь, «взять серверную» заменяет место и текст, помечает синхронизированной и снимает очередь. Тексты сами не склеиваются.

`400` — тело не по контракту, очередь не стирают, человеку короткая фраза. `401` — фраза про токен, без повтора.

### `GET /v1/notes?since=`

`since` — миллисекунды последней успешной синхронизации, для первого запуска `0`. Ответ `200` — массив записей в форме элемента `items` плюс `hasPhoto`. Запись, которой нет локально, появляется в списке как «на сервере». Локальная запись в состоянии «на телефоне» этим ответом не затирается: она доезжает через batch и при необходимости попадает в `conflicts`.

`GET /v1/photos/{localId}` в J не обязателен. Достаточно локального фото и флага, что на сервере файл есть.

Сервер пишете вы, любым стеком, отдельным каталогом в том же репозитории или отдельной командой в README. В Ступенях его нет специально. Проверка, которую копирует ревьюер (хост и токен подставьте свои):

```bash
curl -sS -H "Authorization: Bearer $TOKEN" "http://127.0.0.1:8080/v1/notes?since=0"
```

В README лежит пример ответа и пример batch. Секрета в примере нет.

## Hilt

Граф собирает Hilt. ViewModel получает интерфейсы через конструктор `@HiltViewModel`. Activity не вызывает `NoteApi` и не создаёт `Room` руками.

Интерфейсы, на которые вы показываете пальцем:

- репозиторий записей;
- API;
- часы (их подменяют в тесте);
- показ уведомления;
- источник пуш-токена;
- планировщик синхронизации и напоминания.

Koin в этот репозиторий не добавляют. На собеседовании вы объясняете, что тот же граф читается в `module { single { } }`, если в вакансии Koin.

## Фон и пуш

Синхронизация — `CoroutineWorker` и уникальная работа с одним именем. Кнопка «синхронизировать» ставит в очередь ту же работу, а не второго работника на каждое нажатие. Ограничение сети — `NetworkType.CONNECTED`. Низкий заряд в продукте запрещает старт: и в `Constraints`, и в правиле `shouldEnqueueSync` из лаборатории. Пустая очередь работу не ставит. Уже идущая работа не дублируется.

Напоминание о конце смены — отдельная уникальная работа до ближайших часа и минуты из настроек. Она показывает уведомление и заново ставит себя на завтра. Канал уведомлений один, имя понятное. На API 33 и выше разрешение спрашивают у человека.

Пуш — data-сообщение, не готовый текст от консоли, который приложение не разбирает. Разбор полей совпадает с `parsePush`: `type=shift_reminder` и `type=sync_nudge` с целым `pending` без ведущего нуля. Мусор не роняет процесс. Сервис показывает уведомление через тот же класс, что и локальное напоминание, и для `sync_nudge` только ставит уникальную синхронизацию. Сеть и базу внутри сервиса не крутят.

Транспорт один, на выбор:

- FCM, если на телефоне есть Google Play services. Обзор: [FCM на Android](https://firebase.google.com/docs/cloud-messaging/android/client).
- RuStore Push, если Play services нет или вы сознательно целитесь в устройства без них. Обзор, не версия SDK: [пуш-уведомления RuStore](https://www.rustore.ru/help/sdk/push-notifications). Номер SDK берут со страницы Kotlin/Java в день проекта. Для доставки нужны приложение в консоли RuStore, прошедшее модерацию, совпадение подписи и дистрибьютор на устройстве. Это пишут в README честно.

В README одна фраза, какой транспорт включён и какой сознательно не подключали. Оба сразу через Universal Push — уровень **M**, для J не нужен.

Канал: [уведомления и каналы](https://developer.android.com/develop/ui/views/notifications/channels), разрешение: [POST_NOTIFICATIONS](https://developer.android.com/develop/ui/views/notifications/notification-permission).

## Тесты и CI

Без эмулятора, в CI:

- свёртка очереди;
- правило постановки синхронизации;
- ViewModel: репозиторий на MockK, снимок `StateFlow` читает Turbine. Сохранение в авиарежиме даёт запись «на телефоне». Повторное нажатие во время сохранения не зовёт репозиторий второй раз.

Локально, эмулятор или устройство:

- один тест кадра Compose: на пустом снимке виден текст «Пока пусто»; на снимке с одной записью видно её место. ViewModel в этом тесте не создают.

GitHub Actions на push и на pull request гоняет юнит-тесты. Эмулятор в CI не требуется. JDK в workflow совпадает с README. Секреты в YAML нет. Имена действий `checkout` и `setup-java` сверяют с Marketplace в день коммита, из урока CI их не копируют вслепую.

Документация тестов: [локальные тесты](https://developer.android.com/training/testing/local-tests), [кадр Compose](https://developer.android.com/develop/ui/compose/testing), [MockK](https://mockk.io/), [Turbine](https://cashapp.github.io/turbine/).

## Вехи

Ориентир при 4–6 часах в неделю после домашних работ трека. Это не дедлайн работодателя. Каждая веха — отдельный осмысленный коммит или короткая ветка.

### M0. Репозиторий (вечер)

Публичный репозиторий, лицензия, gitignore, README из заголовков, в тексте честно «записи ещё нет». Проект Android Studio открывается. Workflow зелёный на юнит-тесте, который проверяет хотя бы идентификатор приложения. Дата, когда хотите закрыть M7, стоит в README.

Готово, когда незнакомый человек понимает, что появится, и не находит токенов.

### M1. Запись без сети (неделя)

Список и редактор. Room. Сохранение в авиарежиме, убийство процесса, запись на месте. Пустой список — своя фраза. Сети в этом коде ещё нет.

Готово, когда самолётный режим не мешает перечитать свою строку.

### M2. Фото и настройки (неделя)

Одно фото, сжатие на Default, ориентация не врёт. Имя и время напоминания в DataStore переживают перезапуск.

Готово, когда фото узла открывается из записи после перезапуска.

### M3. Очередь и кнопка синхронизации (неделя)

Hilt, Retrofit, свёртка очереди, ручная кнопка. `curl` из README совпадает с сервером. Конфликт показывается и разбирается двумя действиями.

Готово, когда запись, сделанная без сети, после включения сети и нажатия кнопки видна через `GET`.

### M4. Фон (несколько вечеров)

Уникальный `CoroutineWorker`. Кнопка ставит ту же работу. Пустая очередь и низкий заряд работу не ставят. Повторный тап не плодит работников.

Готово, когда вы включаете сеть и видите уход очереди без второго нажатия, либо честно ждёте ограничение и показываете это в логе WorkManager.

### M5. Тесты (неделя)

MockK, Turbine, тест кадра. CI зелёный на юнит-тестах. Команда прогона записана в README. Тест кадра в CI не обязателен.

Готово, когда сломанная свёртка очереди красит workflow.

### M6. Напоминание и пуш (неделя)

Канал, разрешение, локальное напоминание в выбранный час, один транспорт data-пуша. Сервис пуша не ходит в сеть сам.

Готово, когда уведомление «закройте смену» видно либо от локальных часов, либо от тестового сообщения из консоли выбранного транспорта. В README написано, что из двух транспортов не подключено.

### M7. Портфолио (несколько вечеров)

README заполнен. Есть один PR с текстом. В резюме черновик из четырёх строк и ссылка. Скриншот без чужих адресов и лиц — по желанию.

Готово, когда рубрика ниже без нулей по строкам J.

## Критерии приёмки

J сдан, когда все пункты ниже выполнены.

- [ ] Запись с местом и текстом сохраняется без сети и читается после перезапуска.
- [ ] Пустой список отличим от ошибки сети.
- [ ] Одно фото сжато, лежит файлом, в базе нет блоба, ориентация камеры не переворачивает кадр.
- [ ] Имя и время напоминания живут в DataStore.
- [ ] Очередь сворачивается по правилам лаборатории, тест это фиксирует.
- [ ] `POST /v1/batch`, `PUT` фото и `GET /v1/notes?since=` совпадают с README и с `curl`.
- [ ] Конфликт не склеивает тексты: два явных действия.
- [ ] Hilt, ViewModel зависит от интерфейсов.
- [ ] Main-safety: IO, Default и главный поток разведены.
- [ ] Уникальная фоновая синхронизация с сетью и запретом на низкий заряд.
- [ ] Канал уведомлений, локальное напоминание, один пуш-транспорт data-сообщениями.
- [ ] MockK и Turbine на сохранение, один тест кадра Compose, юнит-тесты зелёные в GitHub Actions.
- [ ] В git нет токенов и keystore.
- [ ] README на двух языках, ограничения названы, DeskNode и станц не выдаются за этот продукт.
- [ ] Есть хотя бы один PR с описанием, как проверить.

Ноль по любому пункту J — к отклику с этим репозиторием рано.

| Польза | это список дел или привычки | журнал с местом, но без фото и без офлайна | место, текст, фото, авиарежим, запись на месте завтра |
| Офлайн | без сети сохранение теряется | сохраняется, после убийства процесса пропадает | переживает процесс и перезапуск |
| Очередь | шлёте сырой список кликов | сворачиваете часть операций | правила лаборатории, CREATE+DELETE не едет на сервер, тест зелёный |
| Конфликт | последняя запись молча затирает другую | конфликт виден, действие одно | две кнопки, тексты не склеены |
| Сеть | таймаутов нет или токен в git | контракт совпал, таймаут один на всё | таймауты в README, 400 и 401 не повторяются, `curl` копируется |
| Потоки | сеть или JPEG на главном | уехало с главного, кнопки спамятся | IO, Default, главный, повторный тап не плодит работу |
| DI | граф собирает Activity | Hilt есть, ViewModel сама создаёт API | интерфейсы, в тесте репозиторий подменён |
| Фон | новый Worker на каждый тап | уникальное имя есть, ограничения забыты | то же имя, сеть, низкий заряд, пустая очередь молчит |
| Пуш | уведомления нет | канал и локальные часы есть, сервис ходит в сеть сам | data-сообщение разбирается, транспорт назван, RuStore или FCM объяснены оба, подключён один |
| Тесты | только ручной прогон | юнит-тесты локально | MockK, Turbine, кадр Compose, CI зелёный |
| Честность | «прод», «middle», чужой репозиторий | личный проект, README обещает лишнее | резюме, README и то, что включается на телефоне, совпадают |

Junior-порог: нет нулей по строкам J, честность равна 2. Этот репозиторий сам по себе должность middle не даёт.

**M**, если остались силы, один пункт:

- второй транспорт через официальный Universal Push RuStore, с той же разборкой data;
- или догрузка фото с `GET /v1/photos/{localId}` на втором телефоне.

Плюс полстраницы `docs/sync.md`: телефон — источник правды, пока запись «на телефоне»; сервер — источник правды для уже синхронизированных; конфликт всегда спрашивает человека.

## Демо на три минуты

1. Авиарежим, новая запись, фото, убийство процесса, запись на месте.
2. Сеть включена, очередь уходит, `curl` показывает ту же строку.
3. Уведомление о смене или тестовый data-пуш.
4. Зелёный прогон CI.

Фраза о себе: «Сделал офлайн-журнал смены: Room, очередь исходящих, Retrofit, Hilt, WorkManager и один пуш-транспорт. Пользуюсь сценарием конца смены, коммерческой установки нет.»

## Если застряли

Один слой за вечер: сначала запись в базе, потом фото, потом `curl`, потом фон, потом пуш. Чужой «полевой CRM» с GitHub не копируют. Намёк [hint-capstone.md](../solutions/hint-capstone.md) открывают, если одна веха стоит около 40 минут и вы уже можете сказать, на каком слое стоите. Готового приложения в намёке нет.

Капстоун [DeskNode](../../career/capstone/SPEC.md) не заменяют этим журналом и не бросают, если он уже начат. Это второй проект, про другой день.
