# Самостоятельная: канал и data-пуш

**Модуль:** A7. Найм Android, стек СНГ  
**Уровень:** J  
**Время:** один-два вечера в `hire-scratch`  
**Лаборатория:** `PushTest`  
**Намёк:** [solutions/hint-push.md](solutions/hint-push.md)  
**Дальше:** [WorkManager](15-work.md)

## Цель

Показать настоящее уведомление с одного транспорта и не уронить разбор мусорной карты.

## Зачем это вам

Лаборатория не видит канал и разрешение. Телефон видит. На собеседовании вас попросят прислать тестовое сообщение. Эта работа как раз про кнопку в консоли и про шторку уведомлений.

## Теория

Если есть Google Play services, подключайте FCM (сервис Google для отправки push-уведомлений на телефоны) и пришлите data-сообщение из консоли Firebase. Если Play services нет или вы сознательно готовитесь к устройствам без них, подключайте RuStore Push (пуш — отправка ваших коммитов на сервер, например на GitHub) и выполните условия консоли. Второй SDK (набор инструментов для разработки под платформу) не добавляйте.

Если за этот вечер консоль не пускает (нет аккаунта, модерация не прошла), планка не обнуляется при трёх условиях: канал и разрешение работают, локальная кнопка в отладочном (отладка, дебаг — поиск причины ошибки: остановка программы, просмотр значений, логов) меню вызывает тот же `ShiftNotifier`, что будет звать сервис, в README честно написано «удалённый пуш ещё не доставлен» и назван транспорт, который вы подключите. Для двойки по рубрике удалённое сообщение всё же нужно. Капстоун позже попросит то же самое уже на журнале.

Серверный ключ отправки в git не кладут. Токен (секретная строка-пропуск, которая подтверждает, кто вы) устройства в README не вставляют.

## Разбор на примере

Отладочная кнопка передаёт в нотификатор команду напоминания. Шторка показывает канал, который вы создали. Затем то же делает сервис, когда консоль присылает `type=shift_reminder`. Сообщение `pending=foo` не показывает ничего и не роняет приложение.

### Рубрика

| Часть | 0 | 1 | 2 |
| --- | --- | --- | --- |
| Лаборатория | `PushTest` красный | зелёный, мусорный pending путаете | зелёный, можете разобрать три карты вслух |
| Канал | уведомления нет | канал есть, разрешение не спрашивают | канал, разрешение, шторка показывает вашу фразу |
| Транспорт | оба SDK сразу или ни одного и нет абзаца | локальная кнопка есть, консоль не пройдена, это написано | одно удалённое data-сообщение дошло, второй транспорт объяснён |
| Секреты | ключ отправки в git | токена в git нет, README молчит про транспорт | токена нет, транспорт и ограничения названы |
| Честность | сервис скопирован из образца SDK целиком | намёк открыт сразу | разбор и нотификатор ваши |

Ноль по лаборатории, каналу, секретам или честности — к WorkManager рано. Единица по транспорту допустима, если README не делает вид, что пуш уже ходит с сервера.

## Типичные ошибки

- Проверить только лог (журнал, куда программа записывает, что делает) `onMessageReceived` и не создать канал.
- Положить в репозиторий ключ сервера «чтобы ревьюер (проверка вашего кода другим человеком до того, как изменения попадут в проект) повторил».
- Обещать в README оба транспорта, подключив один.
