# Список файлов: LazyColumn

**Модуль:** 02. Kotlin и Android  
**Время:** около 25 минут  
**Дальше:** [Тема Material 3](12-material3.md)

## Цель

Показать имена файлов на карте станции списком, который не строит все строки сразу, и отличить пустую карту от ещё не пришедшего ответа.

## Зачем это вам

`Column` и цикл рисуют каждого ребёнка в том же кадре. Три имени переживут. Каталог журналов на SD — нет, и прокрутка начнёт стоить весь список на каждом ping. На работе список почти всегда `LazyColumn`. Страница: [списки в Compose](https://developer.android.com/develop/ui/compose/lists).

## Теория

`LazyColumn` составляет только то, что видно, плюс небольшой запас. Элементы описывают в блоке `items`.

```kotlin
LazyColumn(modifier = modifier) {
    items(files, key = { path -> path }) { path ->
        Text(text = path)
    }
}
```

`key` — стабильный идентификатор строки. Для карты станции это путь `logs/morning.csv`. Индекс в `key` ломается, когда список вставили в начало: Compose решит, что строки те же, и состояние строки уедет не туда. Ключ уникален среди видимой ленты. Два одинаковых пути в одном ответе — ошибка контракта, её чинят на плате или в разборе JSON, а не случайным индексом.

Пустой список и «ещё гружусь» — разный снимок. Пустая карта показывает фразу «на карте ещё нет файлов». Загрузка показывает ту же фазу, что ping: кнопки молчат, фраза про ожидание. Пустой `LazyColumn` без текста выглядит как сломанный экран.

Нажатие по строке отдаёт путь наружу: `onFileClick(path)`. Строка не вызывает `POST /v1/publish` сама. Иначе список знает про OkHttp, и тест клика поднимает сокет.

Длинный каталог с заголовками («гифки», «звук») помечают `contentType`, чтобы Compose переиспользовал подходящий шаблон строки. Пока строки одного вида, достаточно ключа.

Прокрутку к началу после нового списка делают эффектом, если продукт этого просит. Сам `LazyColumn` после нового `files` не обязан прыгать наверх. Для пульта приемлемо остаться там, где человек смотрел, если набор путей тот же.

## Разбор на примере

Плата ответила тремя путями. В снимке `files` — список строк, фаза уже не загрузка. `LazyColumn` показывает три текста. Нажали `logs/morning.csv`. Наружу ушёл этот путь, ViewModel шлёт publish тем же правилом, что одна команда в уроке 03: относительный путь на карте, не путь телефона.

Ответ `[]`. Экран показывает «на карте ещё нет файлов» и не показывает кнопку display. Это не таймаут (предельное время ожидания ответа, после которого ожидание обрывают). Таймаут — фраза «станция не ответила» и пустой список, который не называют пустой картой. Две фразы, как в уроке про ошибку человеку: связь и содержимое путают, если текст один.

Поворот. Ключи те же, лента не мигает чужими строками.

## Упражнения

1. Почему `key = { index -> index }` опасен, если в начало каталога записали новый файл?
2. Какой текст на экране при `files = emptyList()` во время загрузки и какой — когда загрузка кончилась успехом и список пуст?
3. Где живёт вызов publish: в строке списка или выше?

## Типичные ошибки

- `Column { files.forEach { Text(it) } }` на весь каталог карты.
- Ключ-индекс.
- Пустой экран и при загрузке, и при пустой карте.
- `http.newCall` внутри лямбды `items`.
- Класть в `files` локальные `Uri` галереи телефона.
