# Состояние: remember и подъём

**Модуль:** 02. Kotlin и Android  
**Время:** около 30 минут  
**Дальше:** [Побочные эффекты](08-effects.md)

## Цель

Хранить текст поля так, чтобы перерисовка его не стирала, и отдавать это состояние наружу, когда его читает соседний виджет (элемент интерфейса: кнопка, текст, список) или тест.

## Зачем это вам

Composable вызывается снова на каждое изменение. Локальная `var host = ""` при следующем проходе снова пустая, и адресо станции пропадает, пока вы смотрите в Logcat (окно Android Studio с логами приложения и системы). На работе это называют состоянием Compose. Последний успешный хост на диске по-прежнему лежит там, где урок про состояние пульта: в `SharedPreferences` после удачного ping. Память кадра и память «забыть станцию» — разные полки.

Как устроено состояние в текущих доках: [Managing state](https://developer.android.com/develop/ui/compose/state) и [куда его поднимать](https://developer.android.com/develop/ui/compose/state-hoisting).

## Теория

`remember { ... }` считает блок при первом входе composable в композицию и возвращает тот же объект на следующих проходах, пока composable на экране. Для поля нужен не голый `String`, а держатель, чтение которого Compose видит:

```kotlin
var draft by remember { mutableStateOf("") }
```

Запись в `draft` планирует перерисовку тех функций, которые этот `draft` прочитали.

`remember` не переживает уход с экрана и смерть процесса. `rememberSaveable` кладёт значение, которое умеет лежать в `Bundle` (`String`, число, логический), и возвращает его после поворота. Для черновика IP этого хватает на поворот. Для «последний хост после того, как приложение смахнули» по-прежнему нужна запись на диск после успешного ping. Кнопка «забыть станцию» чистит диск и поле. Одной `rememberSaveable` без диска вечер после смены начинается с пустого адреса, если систему выгрузили.

Подъём состояния: поле не прячет строку внутри себя, если строку же показывает подпись или тест. Экран получает значение и лямбду.

```kotlin
@Composable
fun HostField(
    host: String,
    onHostChange: (String) -> Unit,
    modifier: Modifier = Modifier,
) {
    TextField(value = host, onValueChange = onHostChange, modifier = modifier)
}
```

Владелец состояния — ближайший предок, которому строка правда нужна. Пока это один экран, владелец может быть им. Когда строка нужна и списку файлов, и ping, владелец поднимается в ViewModel. Это отдельный урок. Тащить ViewModel в каждую строку списка рано.

Состояние вниз, события вверх. `HostField` не решает, сохранять ли хост на диск. Он сообщает, что человек изменил текст.

## Разбор на примере

Открыли пульт. Диск вернул `192.168.10.1`, экран положил его в состояние поля. Человек дописал пробел и нажал «Проверить». Наружу ушла уже обрезанная строка. В поле остался черновик, который он видит. Успешный ping записывает на диск обрезанный хост.

Повернули телефон. `rememberSaveable` вернул черновик. Убили процесс из списка недавних. Диск вернул последний успешный хост, недописанный пробел сгорел. Это нормально: на диск кладут то, что уже ответило `OK`, а не каждый символ.

Тест экрана потом передаст `host = "10.0.0.2"` аргументом и проверит, что поле показало эту строку. Ему не нужен диск телефона.

## Упражнения

1. Черновик IP лежит в `var` внутри composable без `remember`. Что увидите после того, как придёт фраза ping и функция выполнится снова?
2. Зачем кнопке «забыть станцию» две полки, диск и поле, а не только `rememberSaveable`?
3. Кому принадлежит строка хоста, если её рисует поле и в ту же строку смотрит подпись «сейчас проверяю этот адрес»?

## Типичные ошибки

- Хранить рабочий адрес только в `remember` и удивляться пустому полю после свайпа приложения.
- Писать на диск каждый символ `onValueChange`, включая опечатку.
- Прятать `mutableStateOf` внутри `HostField`, когда родителю нужна та же строка.
- Путать черновик поля и фазу «идёт запрос». Фаза — снимок экрана из карьерного редьюсера (функция «старое состояние + событие = новое состояние»), не второй случайный флаг рядом.
