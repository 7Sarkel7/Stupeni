# OkHttp, таймауты и cleartext

**Модуль:** 02. Kotlin и Android  
**Время:** около 30 минут  
**Дальше:** [Одна команда: показать файл](03-display.md)

## Цель

Собрать короткий запрос `GET /v1/reading` клиентом с конечными таймаутами, закрыть тело ответа, пустить обычный `http://` на Android и не смешивать этот клиент с клиентом облака.

## Зачем это вам

Корутина сама по себе на плату не ходит. Нужен HTTP-клиент с понятными пределами ожидания. У станца два разных разговора: локальная сеть без TLS и позже облако с JWT. Один клиент «на все URL» получает либо слишком короткий таймаут для заливки файла, либо слишком длинный для ping, и таскает заголовки авторизации туда, где их не ждут.

## Теория

Минимальный клиент локальной сети:

```kotlin
class Esp32WifiClient(host: String) {
    private val baseUrl = normalize(host)
    private val http = OkHttpClient.Builder()
        .connectTimeout(5, TimeUnit.SECONDS)
        .readTimeout(5, TimeUnit.SECONDS)
        .build()

    fun ping(): Result<String> = runCatching {
        val request = Request.Builder()
            .url("$baseUrl/v1/reading")
            .get()
            .build()
        http.newCall(request).execute().use { response ->
            val body = response.body?.string().orEmpty()
            if (!response.isSuccessful) {
                throw IllegalStateException(body.ifBlank { "HTTP ${response.code}" })
            }
            body
        }
    }
}

fun normalize(host: String): String =
    if (host.startsWith("http://") || host.startsWith("https://")) host.trimEnd('/')
    else "http://${host.trimEnd('/')}"
```

На что смотреть:

- **Полный URL.** `/v1/reading` без хоста — это не запрос к станцу. Хост — `http://192.168.10.1` или тот IP, который станц получил в домашней сети.
- **`use`.** Ответ и сокет закроются и при исключении. Забыли закрыть — пул соединений со временем начинает вести себя как «сеть устала», хотя плата жива.
- **`isSuccessful`.** Это диапазон 200–299. Тело `SD unavailable` при коде 503 — провал, не строка успеха. Тело как раз стоит положить в исключение, чтобы Toast показал причину.
- **Таймаут.** Для ping хватает нескольких секунд и на соединение, и на чтение. Заливка мегабайтов — другой клиент или другой таймаут чтения, на минуты. Не ставьте бесконечное ожидание: повесите вечер на выключенном станце.
- **Схема.** В LAN у станца `http`, порт 80. Если человек ввёл голый IP, допишите `http://`. Самовольный `https://` на SoftAP даст ошибку рукопожатия, похожую на «станц выключен».

С Android 9 обычный HTTP запрещён политикой cleartext. Симптом: curl с ноутбука работает, пульт падает сразу, часто ещё до таймаута, с текстом про cleartext. Лечится не прошивкой, а сетевым конфигом приложения: разрешить cleartext для отладки стола или только для локальных адресов. Это часть фичи «говорить с станцом», её коммитят вместе с клиентом и не прячут в локальной правке, которая есть только на вашем компьютере.

Второй клиент, `PlatformApiClient`, появится с облаком. У него другой хост, заголовок JWT, другие пути (`/dispatch`), другие таймауты. Не прокидывайте туда IP платы и не прокидывайте JWT на `192.168.10.1`. Два класса короче, чем один с пачкой `if (url.contains(...))`.

Повтор на холодный SoftAP остаётся на вызывающей стороне (урок про корутины): до восьми попыток с паузой. Сам `ping()` по-прежнему одна попытка. Так его можно звать и из проверки «нажать ещё раз», без спрятанного цикла.

IP, который сработал, записывают в `SharedPreferences`, а не только в поле Activity. Убили процесс — не вводите адрес заново. Подробнее в уроке про состояние.

## Разбор на примере

Ноутбук видит status, телефон — нет.

1. Logcat: `CLEARTEXT communication ... not permitted`. Контракт платы верный, политика ОС — нет. Правите конфиг, не `server.on`.
2. Либо в логе `https://192.168.10.1/v1/reading` и ошибка TLS. `normalize` насильно поставил https, либо так ввели в поле. Для этого стола нужна схема `http`.
3. Либо `connect timed out`. Телефон не в сети `METEO-…`. Cleartext тут ни при чём: сокет не открылся. Это развилка из модуля отладки, клиент её только честно сообщает.

Когда ping стабилен, тот же каркас `execute().use { }` пойдёт на `POST`. Сменится метод, тело и, для заливки, таймаут. Не сменится дисциплина: IO, закрытие, код ответа, `Result`.

## Упражнения

1. Ping ходит на `https://192.168.10.1/v1/reading` и падает с ошибкой сертификата. Status по `http` с ноутбука живой. Где правка?
2. Зачем у заливки файла `readTimeout` на минуты, а у ping — на секунды? Что будет, если оставить один клиент с таймаутом 5 секунд и лить через него GIF?
3. Ответ 503 с телом `SD unavailable` разобрали как успех, потому что смотрели только на строку. Какая проверка это ловит?

### Ориентир для самопроверки

1. В сборке URL для LAN. Плата на SoftAP не представляет сертификат. `https` здесь ошибка клиента.
2. Пять секунд оборвут медленную запись большого файла на середине. Получится ложный обрыв «нет связи» на живой плате. У заливки свой, длинный предел чтения.
3. `response.isSuccessful` до того, как тело считают полезным статусом. 503 — провал с текстом причины.

## Типичные ошибки

- URL без схемы или с `https` на локальный станц.
- Не закрывать `Response`.
- Игнорировать код и парсить тело в любом случае.
- Один таймаут на ping и на многомегабайтную заливку.
- Один клиент и на JWT облака, и на SoftAP.
- Разрешить cleartext и заодно начать ходить в чужие `http://` в интернете без нужды. Для учёбы ограничьтесь станцом.

## Чеклист

- [ ] `ping()` бьёт в `http://<хост>/v1/reading`.
- [ ] Ответ закрывается через `use`.
- [ ] Код не 2xx становится `Result.failure` с телом ошибки.
- [ ] Таймаут ping измеряется секундами.
