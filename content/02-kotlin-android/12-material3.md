# Тема Material 3

**Модуль:** 02. Kotlin и Android  
**Время:** около 25 минут  
**Дальше:** [Тест UI и BOM](13-testing-bom.md)

## Цель

Обернуть пульт в одну тему Material 3, чтобы цвета и шрифт не собирались по месту в каждом экране.

## Зачем это вам

Без темы каждая кнопка получает случайный цвет, а тёмная комната у станца бьёт белым фоном шаблона. Material 3 — текущая система компонентов Compose: цвет, шрифт, форма, динамический цвет с обоев на Android 12+. Отдельный дизайн-пакет для пульта не нужен. Страница, с которой сверяют имена: [Material Design 3 in Compose](https://developer.android.com/develop/ui/compose/designsystems/material3).

Flutter в модуле 05 тоже говорит «Material 3». Это другая библиотека и другой язык. Виджет Flutter не заменяет `androidx.compose.material3`.

## Теория

`MaterialTheme` стоит один раз вокруг приложения, внутри `setContent`. Экраны читают `MaterialTheme.colorScheme` и `MaterialTheme.typography`. Локальный `Color.Red` на одной кнопке обходит тему, и тёмная схема его не поправит.

Для стола вечером фиксированная тёмная схема спокойнее обоев:

```kotlin
setContent {
    MaterialTheme(colorScheme = darkColorScheme()) {
        RemoteApp()
    }
}
```

Светлую схему оставляют, если телефон сам в светлой теме и вам так виднее днём. Динамический цвет (`dynamicDarkColorScheme` / `dynamicLightColorScheme`) берёт палитру с обоев, ему нужен API 31. На пульте это приятное дополнение, не условие сдачи. Фраза ошибки всё равно должна читаться: если динамический первичный цвет сольётся с фоном, для текста ошибки берут `colorScheme.error`.

Шрифт. Заголовок экрана — `titleLarge`, фраза ping — `bodyLarge`, путь файла — `bodyMedium`. Свой шрифт в репозиторий пульта не кладут, пока нет брендбука. У станца его нет.

Формы кнопок остаются схемами по умолчанию. Скруглять каждый `Button` вручную — второй источник правды рядом с темой.

Компоненты того же пакета, что тема: `Scaffold`, `TopAppBar`, `TextField`, `Button`, `Text`. Иконки, если нужны, — из зависимостей Material Icons, версия придёт с BOM. Расширенный набор иконок тянет вес в APK, для двух кнопок хватает текста.

Студийный `Theme.kt`, если шаблон его создал, читают и сверяют с страницей Material 3. Импорт `androidx.compose.material.MaterialTheme` в этом файле — старая тема. Её заменяют на material3, а не «оставляют, потому что собирается».

## Разбор на примере

Ночь, SoftAP, телефон в тёмной теме. Фон схемы тёмный, кнопка «Проверить» цветом `primary`, фраза «станц не ответил» цветом `error`. Поле хоста — `TextField` той же темы, подсказка «адрес станца» через `label`, не отдельным `Text` случайного размера.

Включили светлую тему телефона. Та же `MaterialTheme` выбирает светлую схему, фраза ошибки остаётся на `error`. Хардкод серого на белом вы бы уже не нашли.

Динамический цвет с фиолетовых обоев покрасил кнопку. Текст на кнопке берётся из `onPrimary`, его не красят вручную в белый: пара `primary` / `onPrimary` как раз для этого.

## Типичные ошибки

- Импорт темы из `androidx.compose.material`.
- `Color(...)` на каждой кнопке.
- Вторая «дизайн-система» из объекта `StationColors` параллельно `MaterialTheme`.
- Белый фон ночью, потому что взяли шаблон и не дошли до схемы.
- Путать виджеты Flutter и composable Android.
