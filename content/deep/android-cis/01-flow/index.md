# Flow и StateFlow: глубокая глава

:::info Короткая версия
В мобильном приложении этому посвящён короткий урок `cis-flow` (≈ 45 минут) и квиз. Здесь то же самое, но подробно, с заданиями на документацию и с практикой в Android Studio. Короткий урок читать заранее не нужно: всё важное пересказано ниже.
:::

**Время:** ≈ 2 вечера по 90 минут (≈ 3 часа). Из них чтение — около часа, документация — 40 минут, практика — остальное.

## Зачем это

Представьте экран приложения «Смена»: в нём список записей, которые приходят из интернета и базы. Данные приходят не разом, а по одной порции, в разное время. Вам нужно, чтобы экран:

- показывал **что-то сразу**, даже когда данных ещё нет;
- не дёргался, если пришло то же самое, что уже показано;
- переставал слушать данные, когда пользователь ушёл с экрана.

Для этого в Kotlin есть `Flow` и `StateFlow`. На собеседовании на junior Android про них спрашивают почти всегда.

После главы вы сможете:

1. объяснить разницу между «холодным» `Flow` и `StateFlow` на примере;
2. собрать экран, где данные живут во `ViewModel`, а экран только рисует;
3. найти в официальной документации ответы на вопросы, которых нет в тексте;
4. сдать работу на ревью через GitHub.

## Слова простыми словами

Каждое слово ниже встретится дальше. Читайте по порядку: следующие слова опираются на предыдущие.

| Слово | Простыми словами | Бытовая картинка |
| --- | --- | --- |
| **Корутина** (coroutine) | Работа, которую можно поставить на паузу и продолжить позже, не блокируя всё приложение | Вы поставили чайник и пошли делать другое, а не стоите над ним |
| **Приостановка** (suspend) | Момент, когда корутина ждёт (сеть, база, таймер) и освобождает место другим | Вы отошли от чайника |
| **Скоуп** (scope) | «Хозяин» корутин: кто их запустил и кто их отменит | Хозяйка кухни: ушла — все дела на кухне прекращаются |
| **Flow** (поток данных) | Последовательность значений, которые приходят по одному | Конвейер: коробки едут одна за другой |
| **Холодный** поток | Не начинает работу, пока на него никто не подписался | Магазин без покупателей: пока никто не пришёл, никто ничего не нарезает |
| **Подписчик / сборщик** (collector) | Тот, кто получает значения: вызывает `collect` | Покупатель у конвейера |
| **Горячий** поток | Работает сам по себе и хранит последнее значение | Табло на вокзале: показывает текущее, кто бы ни смотрел |
| **StateFlow** | Горячий поток с **одним текущим значением**: оно есть всегда | Табло «Поезд прибудет в 12:40» |
| **ViewModel** | Объект, который хранит данные экрана и переживает поворот | Записная книжка, которая не теряется при смене комнаты |
| **Снимок состояния** (state) | Всё, что нужно экрану, чтобы нарисоваться, в один момент | Фотография табло |

:::caution Не путайте
Слово «поток» в русском значит две разные вещи: **thread** (поток выполнения: отдельная «дорожка» работы процессора) и **Flow** (поток данных). В этой главе «поток» — это всегда `Flow`. Про thread будет отдельная глава.
:::
