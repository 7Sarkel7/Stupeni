# Практика: StateFlow экрана

**Время:** ≈ 2 вечера по 90 минут.
**Инструменты:** Android Studio, Git, свой репозиторий на GitHub. Больше ничего не нужно.
**Результат одним предложением:** зелёная лабораторная плюс экран, у которого данные живут во `ViewModel`, а экран только рисует.

:::warning Решения здесь нет
Готового кода задания в репозитории Ступеней нет и не будет. Ревьюер сверяет вашу работу по критериям. Намёк лежит в [`content/android-cis/solutions/hint-flow.md`](https://github.com/7Sarkel7/Stupeni/blob/main/content/android-cis/solutions/hint-flow.md): открывайте после своей попытки.
:::

## Подготовка (10 минут)

1. Создайте **свой** репозиторий `hire-scratch` на GitHub (публичный или закрытый) и клонируйте его.
2. Создайте ветку для задания:

   ```bash
   git checkout -b assignment/cis-flow-1
   ```

   **До:** вы на `main`. **После:** `git branch --show-current` печатает `assignment/cis-flow-1`.
3. Откройте на этом сайте [короткую справку Git](https://git-scm.com/docs/git-switch) на случай, если запутались с ветками.

## Этап 1. Лабораторная (≈ 40 минут)

1. Склонируйте репозиторий Ступеней и откройте лабораторию:

   ```bash
   git clone https://github.com/7Sarkel7/Stupeni.git
   cd Stupeni/content/android-cis/lab
   ```

2. В файле `FlowNotes.kt` напишите функции `normalizeTitle` и `latestById` по условию из [короткого урока `cis-flow`](https://github.com/7Sarkel7/Stupeni/blob/main/content/android-cis/01-flow.md) (раздел «Упражнения»).
3. Запустите тест:

   ```bash
   ./gradlew test --tests dev.stupeni.hire.FlowNotesTest
   ```

   **До:** тест красный. **Действие:** пишете тела функций, запускаете снова. **После:** тест зелёный.

4. Скопируйте свои `FlowNotes.kt` и тест в `hire-scratch` (путь любой, но тест должен запускаться там командой `./gradlew test`). Закоммитьте.

**Точка проверки 1:** в `hire-scratch` зелёный `./gradlew test`.

## Этап 2. Экран (≈ 90 минут, можно на второй вечер)

Сделайте один экран:

- Холодный `Flow` раз в секунду отдаёт **три ваши строки** и завершается.
- `ViewModel` собирает его в `viewModelScope` и публикует `StateFlow`.
- Начальное значение — пустая строка или фраза «ещё нет».
- Корень экрана читает снимок через `collectAsStateWithLifecycle`.
- Кнопки «ещё один сборщик» нет (почему, объяснено в [разборе](./razbor.md), шаг 1).

Добавьте в `notes/flow.md` **ответ на вопрос**: как вы убедились, что сбор прекращается при уходе с экрана (лог, точка останова)?

**Точка проверки 2:** приложение запускается, строки появляются по одной, начальное значение видно сразу. Сделайте скриншот.

## Этап 3. Документация (≈ 40 минут)

Выполните [вопросы 1–4](./docs.md) и запишите ответы в `notes/flow.md`. Вопрос 5 по желанию.

## Критерии приёмки

- [ ] `FlowNotesTest` зелёный, тела функций написаны вами.
- [ ] В проекте нет `GlobalScope`.
- [ ] После ухода с экрана сбор прекращается вместе со скоупом, и вы можете это показать (лог или точка останова).
- [ ] Повтор одинаковой строки не обязан мигать кадром: у `StateFlow` сравнение по `equals`.
- [ ] В репозитории Ступеней нет ваших файлов решения.
- [ ] `notes/flow.md` содержит ответы на вопросы 1–4 с цитатами.
- [ ] Коммитов несколько, и сообщения объясняют, что и зачем.

## Сдача на ревью

Ревьюер — ИИ-агент. Он читает ваш PR и сверяет с критериями выше.

1. Убедитесь, что `git status` чистый и `./gradlew test` зелёный.
2. Отправьте ветку:

   ```bash
   git push -u origin assignment/cis-flow-1
   ```

3. На GitHub откройте **Pull Request из `assignment/cis-flow-1` в `main` вашего же репозитория** (не в Ступени).
4. В описании PR напишите: что сделано; скриншот экрана; вывод `./gradlew test`; где в `notes/flow.md` ответы; на чём застряли.
5. Ждите комментарии. Исправления делайте **новыми коммитами в ту же ветку**, а не новым PR.
6. Когда ревьюер принял работу, отметьте главу на сайте и сделайте merge.

:::note Шаблон
Шаблон репозитория со сдачами (`stupeni-workbook`) с готовым шаблоном PR появится отдельным шагом. До тех пор используйте `hire-scratch` и описание PR по списку выше.
:::

## Рубрика ревью

| Пункт | Что проверяется |
| --- | --- |
| Работает | Тест зелёный, экран запускается |
| Читается | Нет `GlobalScope`, `ViewModel` не знает про `Composable` |
| Коммиты | Осмысленные сообщения, несколько штук |
| Доки | Ответы с цитатами, есть своими словами |

## Если застряли

1. Перечитайте [разбор](./razbor.md), шаг, к которому относится проблема.
2. Прочитайте текст ошибки целиком: в Logcat и в окне Build.
3. Откройте нужную страницу из [списка доков](./docs.md).
4. Только после этого откройте намёк по ссылке выше.
