# Намёк. 01-git-11-interview

Откройте после своей попытки. Это короткий ключ к устным вопросам урока, не решение практической работы модуля.

1. Пока `main` впереди, merge (мерж — слияние, то есть объединение изменений одной ветки Git с другой) даёт коммит (сохранённый в Git снимок изменений с подписью) с двумя родителями, старые SHA (SHA, хеш — уникальный идентификатор коммита из букв и цифр) живы. Rebase (ребейз — перенос ваших коммитов поверх другого, более свежего коммита, чтобы история выглядела прямой) переносит ваши коммиты поверх нового `main`, это уже другие SHA. Fast-forward (простое слияние, при котором Git лишь передвигает указатель ветки вперёд) бывает, когда двигать нужно только указатель.
2. На общем `main` — `git revert SHA` и обычный `git push`. Amend (дописывание или исправление последнего коммита вместо нового) и `--force-with-lease` уместны на своей ветке, когда переписываете коммит, который не стал базой для чужой работы, и об этом написано в PR (pull request — просьба на GitHub проверить ваши изменения и добавить их в основную ветку).
3. `git fetch` только скачает объекты и обновит `origin/*`, грязные файлы останутся. `git pull` ещё и вливает: на тех же файлах получите отказ `would be overwritten` либо коммит слияния, если дерево чистое и вы разъехались.
4. Тег (постоянная метка на коммите, обычно с номером версии) вперёд не едет, коммит в detached HEAD (указатель Git на коммит, на котором вы сейчас стоите) тег не двигает. Сохранить эксперимент: `git switch -c experiment/from-tag`, не уходя на `main` раньше.
