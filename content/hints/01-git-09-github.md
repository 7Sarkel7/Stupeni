# Намёк. 01-git-09-github

Откройте после своей попытки. Это короткий ключ к устным вопросам урока, не решение практической работы модуля.

1. В описании есть поведение: хендлер (обработчик: код, который принимает событие или запрос и реагирует на него) больше не декодирует GIF, только путь и флаг. Проверка: POST с путём, ответ быстрый, кадр рисует цикл прошивки. Вне PR (pull request — просьба на GitHub проверить ваши изменения и добавить их в основную ветку): сам декодер, облако, секреты, переформатирование несвязанных файлов.
2. Amend (дописывание или исправление последнего коммита вместо нового) меняет SHA (SHA, хеш — уникальный идентификатор коммита из букв и цифр), на который уже ссылается комментарий. Ревьюер (проверка вашего кода другим человеком до того, как изменения попадут в проект) видит другой коммит (сохранённый в Git снимок изменений с подписью) и теряет нитку. Новый коммит оставляет замечание и ответ рядом. Переписывание — только по явной просьбе и с force-with-lease.
3. Открывают шаг `flutter test` (или тот, что красный) и читают первое сообщение падения. Re-run повторяет тот же коммит. Починка — коммит с исправлением и новый push (пуш — отправка ваших коммитов на сервер, например на GitHub).
4. Квартальная прошивка с `develop` — git flow. Ежедневные вливания в `main` — trunk-based. Вопрос для станции: как часто вы готовы прошивать и кто ещё клонирует (клон — полная копия репозитория с историей на вашем компьютере) репозиторий. Один человек вечером обычно живёт короткими ветками от `main`.
