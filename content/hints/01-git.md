# Намёк. 01-git

Откройте после своей попытки. Это короткий ключ к устным вопросам урока, не решение практической работы модуля и не команды, которые можно сдать вместо своих.

1. У корневого коммита (сохранённый в Git снимок изменений с подписью) строки `parent` нет: это первый снимок. Строка `tree` — SHA (SHA, хеш — уникальный идентификатор коммита из букв и цифр) дерева. `git ls-tree HEAD` показывает файлы этого дерева, у вас там `status.txt`. Родителя нет, потому что ссылаться ещё не на что.
2. `git rev-parse HEAD` не меняется: вы не создавали коммит. Правка в секции `Changes not staged for commit`, то есть только в рабочем дереве.
3. `git diff` показывает число, которое сейчас на диске, против индекса. `git diff --staged` показывает число, которое вы добавили, против последнего коммита. После второй правки это два разных `timeout_ms`. В следующий коммит попадёт индекс, пока вы снова не сделаете `git add`.
4. Новый коммит — новый объект: другое дерево и родитель, равный SHA первого. Хеш из-за этого другой. Если подменить байты первого объекта, второй всё ещё хранит старый SHA родителя. Проверка объекта по хешу разойдётся с содержимым, цепочка перестанет сходиться.
