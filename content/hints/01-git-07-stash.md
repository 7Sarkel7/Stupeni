# Намёк. 01-git-07-stash

Откройте после своей попытки. Это короткий ключ к устным вопросам урока, не решение практической работы модуля.

1. Строка ошибки содержит `would be overwritten by merge` и просит commit (коммит — сохранённый в Git снимок изменений с подписью) или stash (стэш — временный «карман» Git для незакоммиченных правок). Три команды: `git stash push -m "..."`, `git merge main` (или `git pull`, если обновляете отслеживаемую ветку), `git stash pop`.
2. Без конфликта `apply` оставляет запись, `pop` удаляет её. С конфликтом `pop` тоже оставляет запись. `drop` после этого отдельный шаг.
3. Флаг `-u`. `-a` заберёт игнорируемые пути вроде `build/` и может захватить `.env`, если он попал в ignore, а вы потом покажете diff (дифф — список отличий между двумя версиями файла: что добавили, что убрали) полки не тому человеку.
4. Файл звуковой ветки верните к снимку: `git restore --source=HEAD --worktree --staged -- путь`. Чистый pop уже снял запись со списка. Объект stash ещё может пожить недостижимым, пока Git не собрал мусор: `git fsck --unreachable`, затем `git show SHA` и, если это та полка, `git stash apply SHA`. Это запасной люк. Рабочая привычка — `apply`, прочитать diff, потом `drop`. `clear` после ошибки только добивает остальные полки.
