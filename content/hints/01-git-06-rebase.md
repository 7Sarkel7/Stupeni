# Намёк. 01-git-06-rebase

Откройте после своей попытки. Это короткий ключ к устным вопросам урока, не решение практической работы модуля.

1. Останется сообщение первого коммита (сохранённый в Git снимок изменений с подписью), у вас это `wip`, если вы не ставили `reword`. Diff (дифф — список отличий между двумя версиями файла: что добавили, что убрали) второго вошёл в него. SHA (SHA, хеш — уникальный идентификатор коммита из букв и цифр) новый, потому что родитель, дерево или состав объекта уже не те, что у старого `wip`. Старый SHA ещё в `git reflog`.
2. Верхний блок — `main`, база rebase (ребейз — перенос ваших коммитов поверх другого, более свежего коммита, чтобы история выглядела прямой). `--ours` в этот момент тоже `main`. Ваш таймаут (предельное время ожидания ответа, после которого ожидание обрывают) 800 лежит в нижнем блоке. Слепой `--ours` оставит число из `main` и выбросит задачу ветки.
3. Нужен push (пуш — отправка ваших коммитов на сервер, например на GitHub), который заменит ветку на сервере только если там всё ещё тот кончик, который вы видели. Голый `--force` затрёт чужой коммит, если коллега успел запушить в ту же ветку. Имя осторожной команды — `--force-with-lease`.
4. `git cherry-pick SHA`, стоя на `main`. В `git log` это новый хеш. Сообщение можно оставить прежним, родитель — кончик `main`, не исходная ветка.
